8. Call withTenant() for tenantId
9. Run parallel Promise.all queries:
   - unreadDirect: count unread messages in DIRECT conversations where user is participant and senderId !== userId and createdAt > lastReadAt
   - unreadGroup: count unread messages in GROUP conversations where user is participant and senderId !== userId and createdAt > lastReadAt
   - unreadAnnouncements: count announcements where tenantId AND published=true AND (no read record for this user — simplified: count announcements created after user's last login, or just return total active announcements count for now)
   - pendingNotifications: count notifications where userId AND read=false
10. Return apiSuccess with shape:

```ts
{
  commandBar: {
    unreadDirect,
    unreadGroup,
    unreadAnnouncements,
  },
  domainBadges: {
    conversations: number,    // = unreadDirect + unreadGroup
    announcements: number,    // = unreadAnnouncements
    notifications: number,    // = pendingNotifications
  },
}
```

For the unread count queries, follow the same pattern as /api/messages/unread/route.ts — query conversationParticipants joined with conversations, then count messages after lastReadAt from other senders. But instead of per-conversation counts, aggregate totals by conversation type (DIRECT vs GROUP).

For unreadAnnouncements: Use a simple approach — count published announcements where tenantId AND (expiresAt IS NULL OR expiresAt > now). This gives "active announcements" which serves as a reasonable proxy for "unread" until a proper read-tracking mechanism is built.

For pendingNotifications: Query the Notification table where userId = current user AND read = false.
