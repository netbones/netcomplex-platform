## CONTEXT.md Override Notes

**D-01 Override (envelope at middleware level):** CONTEXT.md D-01 specifies envelope wrapping at the tRPC middleware layer (via `map`/`formatResponse`). This was investigated and found to be technically infeasible: tRPC v11 has no built-in success-response transformation middleware. The per-procedure `toEnvelope()` pattern seen in identity.ts is the correct and only approach for v11 (RESEARCH.md §Alternatives Considered, line 52). All router migration plans (02–05) therefore apply `toEnvelope()` per-procedure rather than via middleware.

**D-04 Override (onError for code rewriting):** CONTEXT.md D-04 specifies implementing canonical code mapping via tRPC `onError`. This was investigated and found to be incorrect: tRPC v11's `onError` callback is for side effects (logging, reporting) only — its return value is ignored. `errorFormatter` is the sole mechanism for rewriting error codes sent to the client (RESEARCH.md Pitfall 1, lines 396–401; tRPC official docs). Plan 01 Task 1 therefore uses `errorFormatter`, not `onError`.
</rationale>
