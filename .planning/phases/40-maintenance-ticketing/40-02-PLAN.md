<action>
Create the following new API route files. All follow the canonical response envelope pattern (apiSuccess, apiCreated, etc.).

**`GET/POST /api/maintenance/teams`** — List/create in-house maintenance teams

- GET: Returns team list for the tenant, filtered by isActive (default: all)
- POST: Body `{ name, trade, contactName? }`. Creates with UUID, tenantId from withTenant()
- Admin-only (require `requests` permission)

**`PATCH/DELETE /api/maintenance/teams/[id]`** — Update/archive team

- PATCH: Update name, trade, contactName
- DELETE: Soft-delete (set isActive=false) — hard delete only if no active assignments
- Admin-only, tenant-isolated

**`GET/POST /api/maintenance/providers`** — List/create service providers

- GET: Returns provider list for the tenant
- POST: Body `{ companyName, contactName?, phone?, email?, trade }`
- Admin-only

**`PATCH/DELETE /api/maintenance/providers/[id]`** — Update/archive provider

- Same pattern as teams

**`GET/POST /api/maintenance/categories`** — List/create tenant categories

- GET: Returns active categories (used by useTenantCategories fallback path)
- POST: Body `{ value, label, description? }`. Enforces tenantId uniqueness on value
- Admin-only

**`PATCH/DELETE /api/maintenance/categories/[id]`** — Update/archive category

- PATCH: Update label, description. value changes not allowed (would break FK references)
- DELETE: Soft-delete (set isActive=false). Check no active requests use this category
- Admin-only

**`POST /api/maintenance/[id]/assign`** — Assign/reassign ticket

- Body: `{ teamId?, providerId?, reason? }`
- At least one of teamId or providerId required
- Creates a RequestHistory entry recording the assignment change
- If previous assignment exists, records it as oldValue
- Supports reassignment from team→provider with reason (e.g. "scope exceeds capacity")
- Admin-only, tenant-isolated
- Returns updated request with team/provider details

Use `withTenant()` for tenant isolation on all routes. Use `requireAnyPermission(['requests'])` for admin guard. Use canonical api-response functions.
</action>
