<action>
Add to prisma/schema/schema.prisma:

1. CredentialType enum:

```prisma
enum CredentialType {
  EMAIL
  PASSKEY
  NOSTR
  LNURL
  OIDC
}
```

2. Identity model:

```prisma
model Identity {
  id        String   @id @default(uuid())
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  deletedAt DateTime?

  credentials Credential[]
  @@map("identities")
}
```

3. Credential model:

```prisma
model Credential {
  id          String         @id @default(uuid())
  identityId  String
  identity    Identity       @relation(fields: [identityId], references: [id])
  type        CredentialType
  email       String?
  publicKey   String?
  fingerprint  String?
  metadata    Json?          @db.JsonB
  revokedAt   DateTime?
  lastUsedAt  DateTime?
  createdAt   DateTime       @default(now())
  updatedAt   DateTime       @updatedAt
  deletedAt   DateTime?

  @@index([identityId])
  @@map("credentials")
}
```

Place both models after the `SettingValueType` enum (before `Setting`) for logical grouping of core identity.

Follow ADVISORY-034 architecture: `email` is a nullable field on `Credential`
(not implied from type=EMAIL), providing enough data for matching at eventual
token linkage. `metadata` is nullable JSONB (can store provider-specific data —
OIDC nonce, LNURL challenge, etc.). `publicKey` and `fingerprint` start optional.
`revokedAt` / `lastUsedAt` support credential lifecycle and audit. `deletedAt`
follows SOFT_DELETE.md.
</action>
