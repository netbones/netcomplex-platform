# Phase 46.1: Platform SaaS Billing Foundation - Context

**Gathered:** 2026-06-25
**Status:** Ready for planning
**Source:** ADR Ingest Express Path (docs/discussions/BILLING.md)

<domain>
## Phase Boundary

Build the platform SaaS billing foundation — the source of truth for tenant subscription plans, payments, and invoicing. This phase creates the billing domain models (BillingPlan, TenantSubscription, TenantInvoice, TenantPayment, BillingAdjustment, BillingEvent) and establishes the pipeline from subscription → tier assignment. Currently `Tenant.tier` is a manually-assigned field; this phase starts the transition to subscription-derived tiers. Full unification with AI billing, dWallet, and provider billing is a long-term goal — this phase focuses on models, checkout, admin, and tenant portal.
</domain>

<decisions>
## Implementation Decisions

### Models

- BillingPlan — name, monthlyPrice, annualPrice, modulesIncluded, pageLimits, seatLimits, aiQuota
- TenantSubscription — active plan, renewal date, status, trial period, cancellation, tenantId
- TenantInvoice — monthly invoice with VAT support, PDF generation, line items
- TenantPayment — Paystack, PayPal, future Stripe
- BillingAdjustment — credits, debits, discounts
- BillingEvent — immutable event stream (SUBSCRIPTION_CREATED, SUBSCRIPTION_RENEWED, PAYMENT_RECEIVED, PAYMENT_FAILED, PLAN_UPGRADED, PLAN_DOWNGRADED, AI_OVERAGE_CHARGED)

### Tier Pipeline

- BillingPlan → TenantSubscription → Tenant.tier
- `Tenant.tier` becomes output of subscription system rather than manually-assigned field

### Plans & Plans

- 46A-01: Billing Domain Models (schema + migration + seed)
- 46A-02: Checkout & Subscription Lifecycle (plan selection, upgrade, downgrade, cancellation, trial management)
- 46A-03: Platform Billing Admin (routes: /api/admin/platform/billing/plans, /subscriptions, /invoices, /payments; widgets: admin-billing-overview, admin-subscriptions, admin-revenue)
- 46A-04: Tenant Billing Portal (/tenant/billing, /tenant/billing/invoices, /tenant/billing/payment-methods)

### Trial Management

- trialEndsAt, convertedAt, conversionSource fields on TenantSubscription
- Required for measuring onboarding effectiveness

### Coupon System

- Coupon, CouponRedemption models
- Needed for launch promotions, HOA partnerships, annual discounts

### Tax Engine

- TaxRate, TaxJurisdiction models
- VAT support (South Africa), future GST/Sales Tax
- Never bake tax rules directly into invoices — use tax configuration tables

### Billing Events

- Immutable event stream: BillingEvent model
- Events: SUBSCRIPTION_CREATED, SUBSCRIPTION_RENEWED, PAYMENT_RECEIVED, PAYMENT_FAILED, PLAN_UPGRADED, PLAN_DOWNGRADED, AI_OVERAGE_CHARGED
- Invaluable for support and auditing

### the agent's Discretion

- Exact payment gateway integration scope (Paystack existing, PayPal existing — reuse patterns from Provider Billing)
- Whether to implement full PDF invoice generation or defer
- Coupon/tax engine depth — full implementation or schema-only with stubs
- Whether to immediately wire Tenant.tier to subscription, or keep manual assignment as fallback during transition
  </decisions>


### Tenant Portal

```text
/tenant/billing                    — current plan, next invoice, payment methods
/tenant/billing/invoices           — invoice history, PDF download
/tenant/billing/payment-methods    — add/remove cards, default
```

### Integration with Phase 104

Phase 104's `getTierQuota()` reads `tenants.tier` directly. After Phase 46A, `Tenant.tier` is derived from active `TenantSubscription.plan.tier`. Phase 104 requires no changes — the column is the same `Tier` enum, just populated by subscription lifecycle instead of manual admin assignment.
</specifics>
