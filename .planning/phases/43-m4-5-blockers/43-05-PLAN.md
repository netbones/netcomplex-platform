<objective>
Install the `validation-better-auth@1.3.4` npm package and wire it into the Better Auth config with Zod schemas for the 4 critical auth endpoints (sign-up, sign-in, forget-password, reset-password). This adds input validation at the request boundary so that malformed payloads are rejected with a 400 + a Zod error message instead of being silently accepted and causing downstream errors.

Purpose: BD issue `ltn` (P2) — defense-in-depth for the auth surface. The 7-day soak will exercise these endpoints heavily (signups, password resets). Without validation, a malformed request could reach the DB layer and either fail with a confusing 500 or (worse) succeed with garbage data. The `validation-better-auth` plugin is the standard way to add Zod-based request validation to Better Auth.

Output: A new file `src/shared/api/auth-schemas.ts` with 4 Zod schemas; a modified `src/shared/api/auth.ts` that imports `validator` from `validation-better-auth` and adds it to the `plugins` array with the 4 schemas wired up. A `package.json` + `pnpm-lock.yaml` change to install the dep. The auth routes still work for valid requests, and now reject invalid requests with 400.
</objective>

From validation-better-auth (npm package, confirmed via `npm view`):

- Default export: `validator` (a function that returns a Better Auth plugin)
- API: `validator([{ path, schema, before?, after? }])` where:
  - `path`: string — Better Auth's internal endpoint path, relative to basePath (e.g., `/sign-up/email`, NOT `/api/auth/sign-up/email`)
  - `schema`: Standard Schema (Zod is compatible) — the request body schema
  - `before`: optional function called before validation (rare use case)
  - `after`: optional function called after validation (rare use case)
- The plugin validates the request body BEFORE the Better Auth handler runs
- On validation failure: returns 400 with a Zod error message in the response body
- On validation success: passes the (validated) body to the Better Auth handler

Zod schema templates (in `src/shared/api/auth-schemas.ts`):

```typescript
import { z } from 'zod';

export const signUpEmailSchema = z.object({
  email: z.string().email('Invalid email format'),
  password: z.string().min(8, 'Password must be at least 8 characters'),
  name: z.string().min(1, 'Name is required').max(100),
  // callbackURL is optional
  callbackURL: z.string().url().optional(),
});

export const signInEmailSchema = z.object({
  email: z.string().email('Invalid email format'),
  password: z.string().min(1, 'Password is required'),
  // rememberMe is optional
  rememberMe: z.boolean().optional(),
});

export const forgetPasswordSchema = z.object({
  email: z.string().email('Invalid email format'),
  redirectTo: z.string().url().optional(),
});

export const resetPasswordSchema = z.object({
  token: z.string().min(1, 'Token is required'),
  newPassword: z.string().min(8, 'New password must be at least 8 characters'),
});
```

Note: The exact field names match Better Auth's internal API. The path strings are the INTERNAL Better Auth paths (relative to basePath `/api/auth`), so `/sign-up/email` validates requests to `/api/auth/sign-up/email`.

## Trust Boundaries

| Boundary                                               | Description                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Anonymous user → /api/auth/\*                          | All Better Auth endpoints are public (no auth required for sign-up, sign-in, forget-password). The request body is untrusted. The `validation-better-auth` plugin validates the body shape BEFORE the Better Auth handler runs.                                                                                                      |
| Authenticated user → /api/auth/\* (with valid session) | The session cookie is the auth credential. The validator plugin still runs on every request (including authenticated ones) so that a stale client sending a malformed payload doesn't bypass validation.                                                                                                                             |
| Better Auth handler → DB                               | The DB layer receives the (validated) payload. The schema's constraints (email format, password min length) are now enforced at two layers: (a) the Zod schema at the request boundary, and (b) the database column constraints (`users.email` is `citext UNIQUE NOT NULL`, `accounts.password` is hashed via Better Auth's scrypt). |
