<objective>
Build a programmatic audit script that verifies every database query inside every tenant-scoped API route is either (a) inside a route that uses `withTenant()` or (b) explicitly whitelisted as cross-tenant by design. The audit must recurse into `v1/tenant/*` re-exports to inspect the canonical route, since re-export files contain zero DB calls of their own. Output a per-route compliance report to `docs/SECURITY_AUDIT_M4.5.md`.

Purpose: BD issue `e0w` (P2) is the largest scope item in Phase 43. The 90-route count in `docs/API_ROUTES.md` shows that `withTenant()` is at the entry handler of each route, but a route can have helper functions called from inside that perform DB queries without `withTenant()`. The audit must catch this. A scripted approach is faster and more repeatable than manual review, and produces a paper trail for the 7-day soak.

Output: Two artifacts — a runnable audit script at `scripts/audit-tenant-isolation.ts` and a compliance report at `docs/SECURITY_AUDIT_M4.5.md`. Small gaps fixed in-place during execution; large gaps documented as `NEEDS-FOLLOW-UP` items.
</objective>

    1. **Imports**: `import { readFileSync, readdirSync, statSync } from 'node:fs'; import { join, relative } from 'node:path'; import { fileURLToPath } from 'node:url';`

    2. **Constants** (hard-coded from docs/API_ROUTES.md):
       ```typescript
       const API_ROOT = join(fileURLToPath(import.meta.url), '..', '..', 'src', 'app', 'api');
       const WHITELISTED_PATHS = [
         '/api/admin/platform/assist', '/api/admin/platform/assist/[id]',
         '/api/admin/platform/tenants', '/api/admin/platform/tenants/[id]',
         '/api/admin/platform/v1/tenants', '/api/admin/platform/v1/onboarding',
         '/api/platform/tenants', '/api/platform/onboarding',
       ];
       const PUBLIC_V1_PATHS = ['/api/v1/public/content', '/api/v1/public/competitions', '/api/v1/public/events', '/api/v1/public/resources'];
       const SYSTEM_V1_PATHS = ['/api/v1/system/flags', '/api/v1/system/health'];
       const AUTH_PATH_PREFIX = '/api/auth';
       ```

    3. **Helper: `findRouteFiles(dir: string): string[]`** — recursive directory walk that returns all `route.ts` files under `src/app/api/`. Excludes `node_modules`, `.next`, and `dist`.

    4. **Helper: `parseReExport(content: string): string | null`** — regex `^export\s+\{[^}]+\}\s+from\s+['"]([^'"]+)['"];?\s*$` to detect single-line re-exports like `export { GET, POST } from '@/app/api/announcements/route';`. Returns the imported path (resolved to absolute filesystem path) or null if not a re-export.

    5. **Helper: `inspectRoute(filePath: string)`** — returns an object:
       ```typescript
       {
         path: string,                // e.g., "/api/admin/activity"
         type: 'tenant-scoped' | 'v1-reexport' | 'platform-cross-tenant' | 'public' | 'system' | 'auth' | 'other',
         status: 'PASS' | 'FAIL' | 'WHITELISTED' | 'NEEDS-FOLLOW-UP' | 'N/A',
         tenantFilterSource: 'withTenant()' | 'withTenantOptional()' | 'platform-admin-check' | 'none' | 'N/A',
         hasDbCalls: boolean,         // true if file contains `db.select`, `db.update`, `db.delete`, or `db.insert`
         hasWithTenant: boolean,      // true if file contains `withTenant(` or `withTenantOptional(`
         isPlatformAdminCheck: boolean, // true if file references `isPlatformAdmin` AND has no withTenant
         notes: string,
       }
       ```

       Logic:
       - If `parseReExport` returns a non-null path → set `type='v1-reexport'`, recurse into the canonical file, and INHERIT its `status` and `tenantFilterSource`. If the canonical also re-exports, follow the chain (max 5 hops to prevent cycles).
       - If path is in `WHITELISTED_PATHS` → `status='WHITELISTED'`, `tenantFilterSource='platform-admin-check'`
       - If path matches `PUBLIC_V1_PATHS` or `SYSTEM_V1_PATHS` → `status='N/A'`, `tenantFilterSource='N/A'`
       - If path starts with `AUTH_PATH_PREFIX` → `status='N/A'`
       - Otherwise:
         - If `hasWithTenant` → `status='PASS'`, `tenantFilterSource='withTenant()'`
         - Else if `hasDbCalls` and no withTenant → `status='FAIL'`, `tenantFilterSource='none'`, `notes='Route touches DB but does not call withTenant()'`
         - Else if no DB calls → `status='PASS'`, `tenantFilterSource='N/A'`, `notes='No DB calls; tenant filter not required'`

    6. **Helper: `buildReport(results: ReturnType<typeof inspectRoute>[]): string`** — generates Markdown content with a header, summary counts, and a per-route table.

    7. **`async function main()`**:
       - Walk API_ROOT, collect all route files
       - Inspect each, store results
       - Sort by status (FAIL first, then NEEDS-FOLLOW-UP, then WHITELISTED, then PASS, then N/A)
       - Print to stdout: summary (`Total: N routes | PASS: X | FAIL: Y | WHITELISTED: Z | N/A: W`)
       - Write the full Markdown report to `docs/SECURITY_AUDIT_M4.5.md` (auto-create the file path; do not require it to exist).
       - Exit with code 0 if no FAIL results; exit with code 1 if any FAIL (so the script can be wired into CI later).

    8. **Bottom of file**: `main().catch(e => { console.error(e); process.exit(1); });`

    The script MUST be ≤ 200 lines. Use only Node built-ins + the imports listed above. Do NOT add new dependencies. The audit logic is intentionally regex-based (not AST-based) to keep the script lightweight and avoid pulling in TypeScript compiler APIs.

    Important:
    - Do NOT modify any route files in this task. The audit is read-only.
    - The script should print `FAIL: 0` as a starting baseline; if it finds any FAIL, document them in the report but DO NOT auto-fix (that's Task 2's job).
