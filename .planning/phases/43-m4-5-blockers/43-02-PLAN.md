<objective>
Fix `MyHomeSpace` property linking for users who own a property via `standardSeats` but have no `profiles` row linked to an ACTIVE `households` record. The current `/api/users/[id]` route only returns a household when the profile→household→property join succeeds. This plan adds a `standardSeats`-based fallback so the MyHomeSpace widget renders the user's property for ALL property owners, not just those who have a household profile.

Purpose: BD issue `cs5` (P2) is the only true user-facing production bug in Phase 43. Property owners see "No property linked to your profile" in MyHomeSpace despite owning a property via `standardSeats`. This is the highest user-impact blocker for the 7-day soak — without it, ~half the seed users (those without a `profile.householdId` link) cannot view their own property.

Output: A single-file fix to `src/app/api/users/[id]/route.ts` that adds a `standardSeats`-based fallback to the existing household construction logic. No client-side changes needed — the MyHomeSpace widget already handles `property: { id, address, unitNumber, type }` shape.
</objective>
