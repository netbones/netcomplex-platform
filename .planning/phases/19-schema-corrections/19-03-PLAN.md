    In src/app/auth-guard.ts, add protection for /platform/admin paths:

    1. After the session check (around line 44, after the `if (!session)` block), add a new check for platform admin paths:

    ```typescript
    // Platform Admin routes require isPlatformAdmin flag
    if (pathname.startsWith('/platform/admin') || pathname.startsWith('/api/admin/platform')) {
      const user = await db
        .select({ isPlatformAdmin: users.isPlatformAdmin })
        .from(users)
        .where(eq(users.id, session.user.id))
        .limit(1);

      if (!user[0]?.isPlatformAdmin) {
        if (pathname.startsWith('/api/')) {
          return NextResponse.json({ error: 'Forbidden - Platform Admin access required' }, { status: 403 });
        }
        return NextResponse.redirect(new URL('/', request.url));
      }
    }
    ```

    2. Also add '/platform' to the publicPaths array so the signup page is accessible without auth:
       Add `'/platform/signup'` and `'/platform/onboarding'` to publicPaths.

    3. The import for `users` and `db` already exists at the top of the file. The `isPlatformAdmin` field was added by Plan 19-01.

    IMPORTANT: This guard checks isPlatformAdmin independently of the Role enum. A user with role=ADMIN but isPlatformAdmin=false cannot access platform admin routes. This enforces the trust boundary from DISCUSSION.md.
