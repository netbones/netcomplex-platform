    **Part A: Add `requireNotSuspended()` to `src/shared/api/auth-utils.ts`**

    Add a new exported function `requireNotSuspended` that:
    - Takes `request: Request` as parameter
    - Gets session via `auth.api.getSession({ headers: request.headers })`
    - If no session, return `{ suspended: false, suspension: null }` (unauthenticated users pass through — auth is checked separately)
    - If session exists, query `platformSuspensions` table: `where(eq(platformSuspensions.userId, session.user.id))` AND `eq(platformSuspensions.isActive, true)` — use Drizzle `and()` to combine
    - If active suspension found, return `{ suspended: true, suspension: { id, suspensionType, reason, description, startDate, endDate, isPermanent, createdById } }`
    - If no active suspension, return `{ suspended: false, suspension: null }`

    Also add a convenience function `throwIfSuspended(request: Request)` that:
    - Calls `requireNotSuspended(request)`
    - If suspended, throws or returns a 403 NextResponse: `{ error: 'Account suspended', suspension: { id, reason, suspensionType, startDate, endDate, isPermanent } }`
    - If not suspended, returns null (easy to use as guard at top of routes)

    **Auto-unsuspension in requireNotSuspended():**
    Inside `requireNotSuspended()`, if an active suspension IS found, additionally check if `endDate` is in the past:
    ```typescript
    if (suspension && suspension.endDate && new Date(suspension.endDate) < new Date()) {
      // Auto-unsuspend: deactivate suspension + reactivate user
      await db.update(platformSuspensions)
        .set({ isActive: false, updatedAt: new Date() })
        .where(eq(platformSuspensions.id, suspension.id));
      await db.update(users)
        .set({ isActive: true })
        .where(eq(users.id, session.user.id));
      return { suspended: false, suspension: null };
    }
    ```
    This ensures that timed suspensions automatically expire on the user's next API request — no cron job needed.

    **Integration into getSessionAndRole():**
    Modify the existing `getSessionAndRole()` function in `src/shared/api/auth-utils.ts` to ALSO return a `suspension` field:
    - After getting the user and role, call `requireNotSuspended(request)` internally
    - Add `suspension` to the return object: `{ session, userId, role, suspension: SuspensionInfo | null }`
    - This way every API route that uses `getSessionAndRole()` automatically gets suspension info
    - The existing callers continue to work — they just ignore the extra field
    - Update the return type annotation to include `suspension`

    **Apply throwIfSuspended to existing API routes:**
    Add `throwIfSuspended()` guard to these existing routes in `src/app/api/users/[id]/route.ts`:
    - `PATCH` handler: add guard at top after auth check
    - `DELETE` handler: add guard at top after auth check

    For each, call `const suspensionGuard = await throwIfSuspended(request); if (suspensionGuard) return suspensionGuard;`
    This prevents suspended users from modifying their own profile or being deleted while suspended.
