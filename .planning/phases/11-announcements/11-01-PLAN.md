1. Create `src/features/announcements/model/types.ts` with:
   - `AnnouncementPriority` type: `'urgent' | 'high' | 'normal' | 'low'`
   - `AnnouncementItem` interface matching the DB schema (id, tenantId, title, content, author, priority, createdAt, expiresAt)
   - `AnnouncementFormData` interface (title, content, author, priority, expiresAt?)

2. Add `announcementSchema` to `src/shared/api/schemas.ts`:
   - title: z.string().min(1).max(200)
   - content: z.string().min(1).max(5000)
   - author: z.string().min(1).max(100)
   - priority: z.enum(['urgent', 'high', 'normal', 'low']).default('normal')
   - expiresAt: z.string().optional() (ISO date string)

3. Create `src/app/api/announcements/route.ts`:
   - GET: List announcements filtered by tenantId (from withTenant). Support `?priority=urgent` and `?active=true` query params (active means expiresAt is null or > now). Use `withTenant()` for tenantId. Return sorted by priority (urgent first) then createdAt desc.
   - POST: Create announcement. Validate with announcementSchema. Require auth + hasPermission('content'). Derive tenantId from withTenant(). Generate id with crypto.randomUUID().

4. Create `src/app/api/announcements/[id]/route.ts`:
   - GET: Single announcement by id, verify tenantId ownership with withTenant()
   - PATCH: Update announcement, require auth + hasPermission('content'), verify tenantId
   - DELETE: Delete announcement, require auth + hasPermission('content'), verify tenantId

Follow the pattern from `src/app/api/competitions/route.ts` and `src/app/api/competitions/[id]/route.ts` — same structure with withTenant(), hasPermission(), and Drizzle queries. Use `revalidateDashboard()` after mutations.
