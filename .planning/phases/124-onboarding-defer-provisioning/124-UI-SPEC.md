## Visual Hierarchy & Focal Points

**Focal point on `/home` landing:** The hero heading "Welcome to NetComplex" draws the eye first (largest type, centered, highest contrast against vellum background), followed by the two action cards.

**Visual hierarchy across the phase:**

| Priority  | Element                                | Rationale                                      |
| --------- | -------------------------------------- | ---------------------------------------------- |
| Primary   | Hero heading, page-level headings      | Largest type (28-32px, 700 weight), first read |
| Secondary | Card CTAs, primary buttons             | Accent color, 16px/700, draws action intent    |
| Tertiary  | Body copy, field labels, sign-out link | Neutral color, 14-16px/400, supportive role    |

**Progressive disclosure:** The sign-up wizard presents one step at a time, revealing only the fields needed for that step. Step 2 is hidden until Step 1 passes validation. This minimizes cognitive load at each step.

**Card hierarchy on `/home`:** "Create a community" card (right/top on mobile) uses the filled gold-vein CTA to establish it as the primary action. "Try a live demo" card (left/bottom on mobile) uses a ghost/outline CTA as the secondary action.

## UI Surface Inventory

### 1. Collapsed Sign-Up Wizard (`/signup`)

**What changes:** Step 1 (Community Details — community name, subdomain, plan) is REMOVED. The wizard collapses from 3 steps to 2 steps:

- **Step 1 (was Step 2):** "Your Information" — first name, last name, email, phone (optional). Label changed to "Create your account", description: "Enter your details to get started with NetComplex".
- **Step 2 (was Step 3):** "Set your password" — password, confirm password. No community summary card (the summary displayed community details that no longer exist at this stage).

**What stays:** The `SignupHeader`, `SignupFormSection`, `SignupCTA` component APIs remain identical. The `useSignupForm` hook drops `communityName`, `subdomain`, `plan` fields from its schema and removes step 1 validation. Submission calls Better Auth's standard `POST /api/auth/sign-up/email` instead of `POST /api/platform/tenants`.

**Post-submit redirect:** On success, redirect to `/verify-email?email=<email>` (preserved from current behavior at `useSignupForm.ts:121`).

**Error states:** Same error banner pattern (`bg-red-50 border-red-200 text-red-700`). Email delivery failures are surfaced (the backend must propagate — see RESEARCH.md §3).

### 2. `/verify-email` Page

**What changes:** No structural UI changes. The page already handles `idle` → `sending` → `sent` → `error` states correctly. Backend changes (`sendOnSignUp: true`, error propagation) make the page functional where it was previously a dead end (F3).

**Existing state coverage (verified in code):**

- `idle`: Shows email input + "Resend verification email" button
- `sending`: Button shows "Sending..." with `disabled` state
- `sent`: Green success banner + "Send again" button
- `error`: Red banner with `errorMsg` from API

**Backend requirement:** `sendVerificationEmail` callback must use `await` (not `.catch()`) so failures propagate to the client (see RESEARCH.md Pattern 3).

**Card specs:**

- Two equal-width cards in a 2-column grid (stack vertically on mobile)
- Demo card (left): Lucide `Eye` icon, lapis-azure accent
- Create card (right): Lucide `Building2` or `Plus` icon, gold-vein accent
- Cards use `bg-white rounded-xl shadow-card border` with 24px internal padding
- Card CTAs: demo = outline/ghost button, create = filled gold-vein button
- Demo card is rendered conditionally behind a feature flag (`enable-demo-tenant`) since G2 (demo path) is unresolved. When flag is off, the create card takes full width.

**Loading state:** Session check while page hydrates → `LoadingSkeleton` (two placeholder cards). No flash of unauthenticated content.

**Empty/return state:** If user navigates away and returns, same two cards. The heading changes to "Welcome back! Ready to create your community?" if they've visited before (detected via `localStorage` key).

**Error state:** If session is missing or expired, redirect to `/sign-in`.

### 4. Relocated Community-Naming Wizard

**What it is:** The SAME `useSignupForm` component (community name, subdomain, plan) previously at sign-up Step 1, now re-served behind authentication.

**Caller contexts:**

- From `/home` landing → "Create Community" CTA → opens wizard (modal or dedicated route `/create-community`)
- From account menu → "Create Community" menu item
- From platform home → "Create a community" link (persistent entry point)

**UI contract:** The wizard UI is **unchanged** from the current `src/app/(platform)/signup/page.tsx` Step 1 content, EXCEPT:

1. **It is no longer a multi-step wizard.** It's a single form: community name + subdomain + plan selection (the three fields from old Step 1).
2. **Header:** No progress indicator (`SignupHeader` with steps). Instead: `<h2>Tell us about your community</h2>` with description.
3. **Submission:** Calls `POST /api/platform/tenants` (now authenticated — requires session). On 409 (slug taken), shows error: "This subdomain is already taken. Please choose another." — user can edit and re-submit.
4. **On success:** Redirect to tenant dashboard (tenant-scoped route, now that tenantId is set).
5. **Loading state:** Button shows spinner + "Creating Community..." (existing behavior from `SignupCTA.tsx:66`).

**Component reuse strategy:**

- Extract the community fields (name, subdomain, plan) + plan fetching logic into a `CommunitySetupForm` component
- Both the old signup page (Step 1 — being removed) and the new post-auth wizard reuse this component
- The form itself uses existing styles: `border-slate-300`, `focus:ring-indigo-500`, plan cards with `border-2 rounded-lg p-4`, subdomain `.netbones.co.za` suffix

### 5. CTA Entry Points — Copy Alignment

**Source:** PlatformHeader (`src/features/platform/ui/PlatformHeader.tsx`), PlatformFooter, HeroSection, PricingCards, PricingCTA, CTASection, features, about pages.

**Current:** "Get Started" → `/signup` (implies instant community creation).

**Required change (G3):** "Get Started" copy is acceptable post-refactor because it now correctly implies "start the sign-up process" (not "start your community"). However, review all CTA labels across:

- `PlatformHeader.tsx:120` — `getStartedText` → keep "Get Started" (resolved: acceptable as-is)
- PricingCards — "Get Started" per-plan CTA → keep
- PricingCTA — "Get Started" → keep
- HeroSection — "Get Started" → keep
- PlatformFooter — "Get Started" → keep
- CTASection — "Get Started" → keep

**Decision (G3 resolved):** No copy change needed. "Get Started" correctly describes the action of beginning the sign-up flow, which no longer instantly provisions a tenant. The `/signup` page itself makes the scope clear (identity-only fields).
