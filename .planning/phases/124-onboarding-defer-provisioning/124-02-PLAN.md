## Trust Boundaries

| Boundary                   | Description                                                                                                |
| -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Client→Better Auth sign-up | Untrusted form input (name, email, password) flows through Zod validation then `authClient.signUp.email()` |
| Session cookie→subdomains  | `crossSubDomainCookies` widens cookie scope; cookie leakage risk to untrusted subdomains                   |

## STRIDE Threat Register

| Threat ID   | Category               | Component                                   | Severity | Disposition | Mitigation Plan                                                                                                                                                                                                                                 |
| ----------- | ---------------------- | ------------------------------------------- | -------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-124-02-01 | Spoofing               | Better Auth sign-up (no email verified yet) | low      | accept      | Users cannot access tenant-scoped resources until email is verified AND tenant is provisioned. `tenantId: null` users have no tenant access. Better Auth's `sendOnSignUp: true` ensures verification gate exists.                               |
| T-124-02-02 | Information Disclosure | `crossSubDomainCookies` cookie scope        | high     | mitigate    | Domain scoped to `netbones.co.za` — only subdomains under our control. `httpOnly` and `Secure` flags set by Better Auth. Verify in DevTools post-deployment that cookie is NOT sent to untrusted origins. Manual verification in VALIDATION.md. |
| T-124-02-03 | Denial of Service      | `sendVerificationEmail` rejection surfacing | low      | accept      | If `sendEmail` throws (Resend API down), Better Auth returns error to client. User can retry. The old `.catch()` pattern silently swallowed failures; now they're visible — this is the intended improvement.                                   |
| T-124-02-04 | Elevation of Privilege | `authClient.signUp.email()` callbackURL     | low      | accept      | `callbackURL: '/verify-email'` — user is redirected to verification page after sign-up. They cannot bypass verification since no tenant resources are accessible without `tenantId`.                                                            |
