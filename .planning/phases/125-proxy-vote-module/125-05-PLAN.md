**proxy-crud.service.ts — MeetingProxy CRUD operations**

<read_first>
- src/features/proxy-vote/model/proxy-vote.zod.ts (createProxySchema, updateProxySchema, signProxySchema, approveProxySchema, rejectProxySchema)
- src/features/proxy-vote/lib/status-transitions.ts (transition() function — MUST be called before every status change)
- src/features/proxy-vote/server/signature/registry.ts (getSignatureAdapter() for INTERNAL)
- src/shared/api/db.ts (db.query / db.select / db.insert / db.update patterns — follow existing Drizzle query conventions)
</read_first>

<action>
Write src/features/proxy-vote/server/proxy-crud.service.ts with functions:

1. `createProxy(db: DrizzleDB, input: CreateProxyInput, tenantId: string, ownerUserId: string, ownerHouseholdId: string): Promise<MeetingProxy>`
   - `CreateProxyInput` from createProxySchema (validated)
   - Validate meeting belongs to tenant: db.query.events with tenantId filter — reject if not found
   - Validate meeting is proxy-eligible: call `isProxyEligible(event.category)` — reject if not eligible
   - Insert row: all fields from input, status=Draft, createdAt=now, tenant context from params
   - Return inserted MeetingProxy row

2. `updateProxy(db, proxyId, input: UpdateProxyInput, userId, tenantId): Promise<MeetingProxy>`
   - Fetch proxy, verify ownerUserId matches userId (owner can update own proxy)
   - If status change: call `transition(currentStatus, event)` before DB update

3. `signProxy(db, proxyId, evidence: SignatureEvidence, userId, tenantId): Promise<MeetingProxy>`
   - Fetch proxy, verify proxyUserId matches userId (proxy must sign their own nomination)
   - Verify status is WaitingForProxy (only proxy can sign after accepting)
   - Call `transition('WaitingForProxy', 'proxyAccepted')`
   - Call getSignatureAdapter('INTERNAL').verify(evidence) — reject invalid signature
   - Update proxy: signatureEvidence=evidence, signatureProvider='INTERNAL', proxySignedAt=now, status='PendingHoaReview'

4. `approveProxy(db, proxyId, approverUserId, tenantId, notes?): Promise<MeetingProxy>`
   - Verify status is PendingHoaReview
   - Generate referenceCode: `PV-{YYYY}-{NNNN}` where NNNN = COUNT(*)+1 transaction-wrapped (RESEARCH.md sequential numbering pattern)
   - Call `transition('PendingHoaReview', 'approve')`
   - Update: status=Approved, approvedBy=approverUserId, approvedAt=now, referenceCode=PV-YYYY-NNNN, notes

5. `rejectProxy(db, proxyId, approverUserId, tenantId, notes: string): Promise<MeetingProxy>`
   - Verify status is PendingHoaReview
   - Verify notes non-empty (Zod enforced, business-logic double-check)
   - Call `transition('PendingHoaReview', 'reject')`
   - Update: status=Rejected, approvedBy=approverUserId, approvedAt=now, notes

6. `withdrawProxy(db, proxyId, userId, tenantId): Promise<MeetingProxy>`
   - Verify ownerUserId matches userId
   - Status can be Draft/WaitingForUpload/WaitingForProxy/PendingHoaReview — any pre-approval state
   - Call `transition(currentStatus, 'withdraw')`
   - Update: status=Withdrawn

7. `getProxyById(db, proxyId, tenantId): Promise<MeetingProxy | null>`
   - Single proxy lookup with tenant scope

8. `getProxiesByMeeting(db, meetingId, tenantId): Promise<MeetingProxy[]>`
   - All proxies for a meeting, tenant-scoped

All functions pass session-level guards: session.userId, session.tenantId (from tRPC ctx). Tenant isolation via DB WHERE clauses.
</action>
