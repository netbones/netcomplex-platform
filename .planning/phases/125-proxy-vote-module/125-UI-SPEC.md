## Spacing Scale

Declared values (multiples of 4, 8-point scale):

| Token | Value | Usage                                                                     |
| ----- | ----- | ------------------------------------------------------------------------- |
| xs    | 4px   | Icon gaps, inline padding, badge gaps, checkmark-to-text spacing          |
| sm    | 8px   | Compact element spacing, card content gaps, step indicator dot gaps       |
| md    | 16px  | Default element spacing, card padding, form field gaps, proxy row padding |
| lg    | 24px  | Section padding, wizard step content padding, signature pad margins       |
| xl    | 32px  | Layout gaps, proxy card grid gaps                                         |
| 2xl   | 48px  | Major section breaks                                                      |
| 3xl   | 64px  | Page-level spacing                                                        |

**Exceptions:**

| Element                       | Value                  | Reason                                                                                                                                                                            |
| ----------------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| All interactive touch targets | 44px minimum (44×44px) | Mobile accessibility. Applies to: Accept/Decline buttons, Approve/Reject buttons, signature canvas hit area, upload button, search result tap targets, drawer handle, CTA buttons |
| Signature canvas hit area     | 44px minimum height    | SignaturePad component: drawing area must be at minimum 44px tall; visual canvas may exceed this                                                                                  |
| QR reference code area        | 44×44px minimum        | QR code display for PV-YYYY-NNNN — scannable at arm's length                                                                                                                      |

All spacing values must be multiples of 4. Any exception above must be explicitly justified by accessibility requirements.

### Focal Point

The primary focal point on the main wizard screen (Step 1 — Attendance) is the **meeting title** displayed at the top of the wizard step content area (`text-lg font-semibold`), which anchors the user in context before they make their attendance choice. On subsequent steps, the focal point shifts to the primary input element: the **search input** (Step 2), the **upload drop zone** (Step 3), the **signature canvas** (Step 5). On the HOA admin widget, the focal point is the **QR reference code** display on approved proxies (`bg-soralia-primary/5` with `text-soralia-primary`), which draws the eye as the actionable verification artifact.

### Visual Hierarchy

**Primary → Secondary → Tertiary visual order across all proxy vote screens:**

1. **Primary layer** — Action inputs: Attendance radio selection, resident search input, upload drop zone, signature canvas, primary CTA buttons. These elements carry the `soralia-primary` accent color and largest visual weight.
2. **Secondary layer** — Status indicators: Step indicator dots (6-dot row), status badges (7-color palette), checkmark rows (✓ Owner Signed / ✓ Proxy Signed / ✓ Form Uploaded), and meeting metadata (date, title, type). These provide at-a-glance progress awareness without competing with inputs.
3. **Tertiary layer** — Supporting copy: Step labels, field labels, empty state messages, error messages, proxy email/phone details, QR reference "Copy" text label. These use `gray-500` text at caption/body weight (400) and recede visually unless the user needs them.

The hierarchy is reinforced by:

- Accent color (`#4F46E5`) appearing only on primary-layer elements
- Status badges using muted tints (`amber-50`, `gray-100`) that don't compete with inputs
- Supporting copy at 14px–16px weight 400 in `gray-500` — low visual weight
- Primary CTAs at 44px minimum touch targets — largest interactive elements on the screen

## Interaction Patterns

### Proxy Flow Wizard (6 Steps)

1. **Trigger:** Owner selects "I cannot attend" on an eligible meeting event (AGM/SGM/Special Resolution/Trustee Election).
2. **Wizard opens:** Full-page or modal overlay with 6-step indicator at top. Step content replaces on progression.
3. **Step 1 — Attendance:** Radio selection "I will attend" / "I cannot attend". "I cannot attend" continues to Step 2.
4. **Step 2 — Appoint Proxy:** ProxySearchBox renders. Owner searches resident OR toggles non-resident. Selection required to proceed.
5. **Step 3 — Upload Form:** ProxyUploadForm renders. Owner uploads signed PDF/JPG/PNG. Upload required to proceed. Creates Draft → WaitingForUpload transition on first save.
6. **Step 4 — Proxy Acceptance:** Idle state — notifies owner that nomination sent. System sends notification to proxy nominee. Status: WaitingForProxy. Owner can withdraw at this step.
7. **Step 5 — Digital Signature:** ProxySignaturePad renders (only after proxy accepts). Proxy draws or types signature. Submit transitions to PendingHoaReview.
8. **Step 6 — Complete:** ProxyStatusCard renders showing submitted status, checkmarks, and "Submitted to HOA. Pending verification."
9. **Withdraw:** Owner can withdraw from any step before HOA approval. Confirmation dialog: "Withdraw Proxy: Are you sure? This action cannot be undone."

### Proxy Acceptance Notification Flow

1. **Nomination sent:** System notification to proxy nominee (in-app + email).
2. **Notification content:** "You have been nominated as a proxy for {ownerName} — {meetingTitle}". Buttons: "Accept Proxy Appointment" / "Decline Proxy Appointment".
3. **Accept path:** Opens signature step (Step 5) — draw or type signature → Submit → Status → PendingHoaReview.
4. **Decline path:** Confirmation dialog → notification to owner ("Proxy declined") → owner returns to Step 2 to appoint new proxy.
5. **Reminder:** System sends reminder notification to proxy if not accepted within configurable window.

### HOA Admin Approval Flow

1. **Widget placement:** HoaProxyWidget in Admin space widget grid.
2. **Pending items:** Proxies with status PendingHoaReview show "Approve Proxy" / "Reject Proxy Appointment" buttons.
3. **Approve:** Clicking "Approve Proxy" transitions status to Approved. Generates QR reference code PV-YYYY-NNNN. Notification to owner ("HOA approved").
4. **Reject:** Clicking "Reject Proxy Appointment" → confirmation dialog → transitions status to Rejected. Optional notes field. Notification to owner ("HOA rejected").
5. **Approved display:** QR reference code displayed in `bg-soralia-primary/5` box with clipboard icon and "Copy" text label. Code format: PV-{YYYY}-{sequential NNNN padded to 4 digits}.
6. **QR rendering:** Static QR code image (generated server-side) displayed at 44×44px minimum for scannability.

### Status Lifecycle Visuals

```
Draft → Waiting for Upload → Waiting for Proxy → Pending HOA Review → Approved / Rejected
                                                                           ↓
                                                                        Withdrawn
```

- **Draft:** Proxy initiated, no form uploaded yet. Gray badge.
- **Waiting for Upload:** Form needs upload. Amber badge + "Upload pending" indicator.
- **Waiting for Proxy:** Form uploaded, awaiting proxy acceptance. Amber badge + "Awaiting proxy" indicator.
- **Pending HOA Review:** Both signatures complete, awaiting HOA. Amber badge + "Under review" indicator.
- **Approved:** HOA approved. Green-tinted accent badge + QR reference.
- **Rejected:** HOA rejected. Red badge + rejection reason if provided.
- **Withdrawn:** Owner withdrew. Gray badge, terminal state.
