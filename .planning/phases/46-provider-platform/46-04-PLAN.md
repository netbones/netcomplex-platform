# Plan 04: Admin Provider Moderation, Due Diligence & Revenue Analytics

## Objective

Create a comprehensive admin interface for **provider moderation, due diligence verification, revenue monitoring, and analytics**. This covers the admin-side operations needed to manage the provider lifecycle: from reviewing registrations, conducting due diligence, monitoring revenue (with platform fees from Paystack/PayPal), moderating providers, and overseeing ecosystem health.

## must_haves

- [ ] Admin dashboard shows all providers with filtering by verification status (pending, probation, verified, suspended)
- [ ] Provider detail view shows full profile, legal agreements, due diligence status, verification history, and revenue records
- [ ] Admin can approve or reject provider applications with notes
- [ ] **Admin can view revenue summary with platform fee breakdown (Paystack vs PayPal, total fees, net provider payouts)**
- [ ] **Admin can monitor payment gateway health and transaction status**
- [ ] Admin can manually adjust credit scores and override automatic verifications
- [ ] Tenant registration mode can be toggled between OPEN and INVITATION_ONLY
- [ ] Admin analytics show provider ecosystem metrics (new registrations, verification rate, credit distribution, revenue)
- [ ] Admin can suspend/reinstate providers with audit trail
- [ ] Admin can view and process refunds for disputed transactions

## Background

With the introduction of verification status, legal adherence, due diligence, community credits, and payment gateway integration, the admin role becomes critically important. This plan creates the administrative interface and APIs for managing the entire provider lifecycle.

## Risks

- **Admin permission escalation:** Ensure all admin endpoints verify role (ADMIN/BOARD) to prevent privilege escalation.
- **Credit score manipulation:** Admin credit adjustments must be logged and auditable.
- **Data privacy:** Admin views must respect tenant isolation.
- **Audit trail completeness:** Every admin action (verify, reject, suspend, credit adjustment, refund) must be logged with timestamp, admin ID, and reason.
- **Refund complexity:** Payment gateway APIs have different refund capabilities and limits. Need robust error handling.
- **Revenue accuracy:** Platform fee calculations must be accurate for accounting purposes. Consider rounding and currency handling.
