# Plan 03: Provider Billing, Subscription, Community Credits & Payment Gateway Integration

## Objective

Implement provider billing and subscription management with **Paystack and PayPal as payment gateways**, **platform fee processing according to the SaaS License Agreement**, and a **community credits system**. Verified providers get premium features at standard rates, while probation providers pay reduced rates with limited capabilities. Community credits track provider trust and performance, enabling automatic verification.

## must_haves

- [ ] Providers can subscribe to tiers using Paystack or PayPal
- [ ] **Platform collects a transaction fee on all payments (platform fee as per SaaS agreement)**
- [ ] **Transaction records include: providerId, amount, platformFee, paymentProcessorFee, netAmount, status**
- [ ] Providers can view their current subscription tier, billing status, payment history, and invoices
- [ ] **Payment setup includes linking Paystack/PayPal account or paying via platform**
- [ ] **Subscription tiers vary by verification status:** Verified providers have full access; probation providers have limited access at reduced cost
- [ ] **Community credits system tracks provider trust and performance metrics**
- [ ] Admin can manage subscription tiers and assign them to providers
- [ ] **Credit thresholds define verification progression: probation → verified**
- [ ] Billing data is persisted in the database with proper tenant isolation
- [ ] Subscription status affects provider feature access (e.g., number of listings, analytics depth, promotion features)

## Background

The SaaS License Agreement (Section 4.7) outlines a revenue sharing model for Platform revenue. The Platform will use Paystack (for South African market) and PayPal (for international) as payment gateways. The Platform collects a platform fee on all transactions, with the remainder going to the provider. The community credits system drives verification status.

**Scope:** Full payment processing with Paystack and PayPal integration, platform fee collection, and DB-tier community credits tracking.

   ```typescript
   const platformFee = transactionAmount * (tier.platformFeePercent / 100);
   const processorFee = gateway === 'paystack' ? transactionAmount * 0.015 : transactionAmount * 0.029; // Example: Paystack 1.5%, PayPal 2.9%
   const netAmount = transactionAmount - platformFee - processorFee;
   ```

## Risks

- **Payment gateway reliability:** Paystack and PayPal have different API behaviors. Need robust error handling and retry logic.
- **Webhook security:** Must verify webhook signatures to prevent fraud.
- **Platform fee disputes:** Clear communication of fee structure is essential to avoid disputes.
- **Currency handling:** ZAR (Paystack) vs USD/GBP/etc (PayPal). Need clear currency conversion or separate pricing.
- **Chargeback handling:** Implement dispute handling for PayPal/Paystack chargebacks.
- **Credit algorithm fairness:** The credit calculation algorithm must be transparent and fair. Consider edge cases (new providers, inactive providers, disputed reviews).
- **Verification threshold tuning:** Credit thresholds need calibration to balance trust with accessibility.
- **Performance:** Credit calculation runs periodically. Consider caching or background job for large datasets.
