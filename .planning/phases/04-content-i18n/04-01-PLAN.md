## Remaining Scope

### 1. Frontend Locale-Aware Content Display

**Current state:** Content API (`/api/content`, tRPC `content.listContent`) now returns locale-resolved flat strings for `title`, `content`, `excerpt`. Content card/page components previously rendered `content.title` as a JSONB object — with the API change, these should now receive flat strings. However, some pages fetch from other endpoints (e.g., `/api/conservation`) or read from internal APIs that don't apply locale transformation.

**Needed:** Audit all content display sites to ensure they consume locale-resolved strings:

- (a) Pages using `/api/content` or tRPC content procedures — ✅ API now returns flat strings, no change needed
- (b) Pages using other endpoints — need locale-awareness added
- (c) Direct DB queries in server components — need `getLocalizedValue()` applied

**Components to audit:**

- Content cards (grid/list views on directory, resources, services, conservation)
- Content detail pages (news, articles)
- Related content sections

### 2. Admin Editing — `_raw` Preservation

**Current state:** `ContentForm` sends/receives JSONB blobs. Admin can see all locales.

**Needed:** Ensure the API response always includes `_raw` (full JSONB) alongside resolved locale strings so the admin editor can switch locales without re-fetching.

`transformContentForLocale()` already returns `_raw` — just needs to be wired into the API response.
