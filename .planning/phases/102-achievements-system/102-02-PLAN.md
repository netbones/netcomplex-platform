  <action>
Create 2 resident-facing API routes:

**src/app/api/achievements/route.ts — GET:**

- Uses `getRLSContext(request)` + `runWithRLS(ctx, ...)` for tenant isolation (per existing pattern)
- Queries `achievementDefinitions` LEFT JOIN `tenantAchievements` ON (definitionId + tenantId)
- Filters: where `tenantAchievements` is null (default-enabled, per RESEARCH Pitfall 2) OR `tenantAchievements.enabled = true`
- LEFT JOIN `userAchievements` ON (definitionId + userId) to get unlock status
- Returns array of `{ id, key, label, description, icon, category, threshold (customThreshold ?? definition.threshold), unlocked: boolean, unlockedAt?: Date }`
- Uses `getSessionAndRole()` to get userId; returns 401 if unauthenticated
- Per D-13: no canAccess() gating — achievements are always-on

**src/app/api/achievements/progress/route.ts — GET:**

- Same auth + tenant isolation pattern
- Queries `userAchievementProgress` WHERE userId matches + tenantId matches
- JOINs `achievementDefinitions` to get label/key/threshold for each progress row
- Returns array of `{ definitionKey, label, count, threshold, percentage: Math.min(100, Math.round(count/threshold*100)) }`
- Only returns rows where the achievement is currently enabled (respecting TenantAchievement.enabled)
  </action>

Create admin PATCH endpoint at `src/app/api/admin/achievements/[id]/route.ts`:

- `[id]` is the AchievementDefinition.id
- Auth: `getSessionAndRole()` + `hasPermission(sessionRole.role, 'admin')` → 403 if not admin
- Rate limit: `rateLimitByUser(sessionRole.userId, { windowMs: 60_000, maxRequests: 20 })`
- Tenant isolation: `getRLSContext(request)` + `runWithRLS(ctx, ...)`
- Request body: `{ enabled?: boolean, customThreshold?: number | null, icon?: string, category?: 'ENGAGEMENT' | 'CONTRIBUTION' | 'MILESTONE' }`
- Upserts `TenantAchievement` row using `onConflictDoUpdate` on `[tenantId, definitionId]`
- Per D-11: disabling sets `enabled = false` on TenantAchievement — does NOT delete UserAchievement rows
- Per D-10: customThreshold overrides the definition's default threshold for this tenant
- Updates icon and category on the AchievementDefinition itself (platform-wide, admin-only)
- Writes audit log: `writeAuditLog({ action: 'ACHIEVEMENT_CONFIG_CHANGED', actorId, tenantId, details: { definitionId, changes } })`
- Returns the updated TenantAchievement + definition state
- Zod validation on body: customThreshold must be positive int if provided; category must be valid enum value
