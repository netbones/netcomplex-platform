Create 4 files in `src/shared/api/achievements/`:

**service.ts** — Core achievement processing logic:

- `processAchievementEvent({ tenantId, userId, eventType })` function
- Queries `achievementDefinitions` where `eventType` matches AND (no `tenantAchievement` row exists OR `tenantAchievement.enabled = true`)
- For each matching definition: atomic upsert on `userAchievementProgress` using `onConflictDoUpdate` with `SET count = count + 1` (per RESEARCH Pitfall 3)
- After upsert, re-select the row to get updated count
- If `count >= threshold` (using `tenantAchievement.customThreshold ?? definition.threshold`): check if `userAchievements` row exists; if not, insert unlock record + optional Notification row
- Uses `db` from `@db/schema` (Drizzle instance), wraps in try/catch with Pino logging
- Per D-11: never deletes UserAchievement rows (historical preservation)
- Per D-16: forward-only counting, no backfill logic

**listener.ts** — Module-level side effect registrations:

- Imports `onEvent` from `@shared/api/events`
- Registers 6 listeners using the ACTUAL event types from emitter.ts (per RESEARCH Pitfall 1):
  - `onEvent('booking.created', ...)` — payload: BookingCreatedEvent
  - `onEvent('maintenance.created', ...)` — payload: MaintenanceCreatedEvent
  - `onEvent('event.rsvp', ...)` — payload: EventRsvpEvent (NOT 'event.attendee.added')
  - `onEvent('content.created', ...)` — payload: ContentCreatedEvent
  - `onEvent('group.joined', ...)` — payload: GroupJoinedEvent (NOT 'group.member.added')
  - `onEvent('competition.entered', ...)` — payload: CompetitionEnteredEvent (NOT 'competition.entry.created')
- Each handler extracts `{ tenantId, userId }` from payload and calls `processAchievementEvent`
- Each handler wrapped in try/catch — listener errors must not propagate (per emitter.ts contract)

**seed.ts** — Seed 12 achievement definitions (per D-04, D-05, D-06):

- One-shot (threshold=1): `first_booking`, `first_maintenance`, `first_event_rsvp`, `first_post`, `first_group_join`, `first_competition_entry`
- Cumulative: `maintenance_5` (5), `maintenance_10` (10), `event_attendee_5` (5), `event_attendee_10` (10), `content_creator_5` (5), `bookings_3` (3)
- eventType values use the ACTUAL emitter types: `booking.created`, `maintenance.created`, `event.rsvp`, `content.created`, `group.joined`, `competition.entered`
- Uses `onConflictDoNothing` on `key` for idempotency
- Export as `seedAchievementDefinitions()` function

**index.ts** — Barrel export:

- Re-export `processAchievementEvent` from service
- Re-export `seedAchievementDefinitions` from seed
- Import listener.ts for side-effect registration (import './listener')
