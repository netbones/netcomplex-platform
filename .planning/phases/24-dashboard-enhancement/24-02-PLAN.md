    src/app/api/groups/membership-requests/route.ts:
    - GET: List membership requests for the tenant.
      - Requires authentication (getSessionAndRole pattern)
      - Requires content permission (hasPermission)
      - Enforce tenant isolation via withTenant()
      - Query groupMembershipRequests joined with users and groups
      - Support query params: status (PENDING/ALL, default PENDING), groupId (filter by specific group)
      - Order by createdAt descending
      - Return: [{ id, userId, groupId, status, message, createdAt, user: { name, email }, group: { name, accessType } }]

    src/app/api/groups/membership-requests/[id]/route.ts:
    - POST: Approve or reject a membership request.
      - Requires authentication and content permission
      - Accept JSON body: { action: 'approve' | 'reject' }
      - If approve:
        1. Update request status to APPROVED
        2. Create a UserGroup record (insert into userGroups) with role=MEMBER
        3. Use withTenant() for tenant scoping
      - If reject:
        1. Update request status to REJECTED
      - Return 200 with updated request
      - Add @@index on status for efficient filtering (if not already present in schema — check first)

    Note: The GroupMembershipRequest model already exists in schema with status enum (PENDING, APPROVED, REJECTED). No schema changes needed.
    Check if MembershipStatus enum has REJECTED — if not, the schema may need an update. The current enum shows PENDING, APPROVED, REJECTED in the schema.
