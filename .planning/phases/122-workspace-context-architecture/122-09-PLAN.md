<objective>
Create a seed script that populates the database with notification records containing property-delegation `link` fields. These records enable manual end-to-end testing of the NotificationLink deep-link flow — clicking "View details" on a notification triggers `inferWorkspaceTarget` → `switchWorkspace` → navigate → toast (D-07). Without seed data, the notifications page shows "No notifications" and the deep-link flow is untestable outside unit tests.

Purpose: Closes the UAT gap where NotificationLink is built and wired (plan 122-03) but has no real notification data to exercise the full E2E flow. The seed records provide the missing runtime data.
Output: A standalone idempotent seed script (`scripts/seed-notifications.ts`) that inserts workspace-related notification records.
</objective>

  <name>Task 1: Create idempotent seed script for workspace notification records</name>
  <files>scripts/seed-notifications.ts</files>
  <action>
Create `scripts/seed-notifications.ts` — a standalone TypeScript script that inserts notification records with workspace-specific `link` fields into the database. Follow the existing seed infrastructure pattern from `scripts/seed-drizzle.ts`.

    **Script structure:**

    1. Import `dotenv/config`, `drizzle-orm/node-postgres`, and the notifications/tenants/users schemas
    2. Create a Drizzle db connection using `DATABASE_URL` from env (matches `seed-drizzle.ts` pattern)
    3. Look up the soralia tenant by slug: `SELECT * FROM tenants WHERE slug = 'soralia' LIMIT 1`
    4. Look up a resident user for that tenant: `SELECT * FROM users WHERE tenantId = $1 AND role = 'RESIDENT' LIMIT 1`
    5. Define a list of seed notification records with property-like link paths:

    ```typescript
    const SEED_NOTIFICATIONS = [
      {
        title: 'New delegation invitation',
        message: 'Sarah Johnson has invited you to manage 14 Palm Avenue. Tap to accept and start managing this property.',
        type: 'info' as const,
        link: '/properties/palm-avenue-14',
        category: 'delegation',
      },
      {
        title: 'Delegation expiring soon',
        message: 'Your access to 22 Sunset Close expires in 3 days. Contact the owner to extend your delegation.',
        type: 'warning' as const,
        link: '/properties/sunset-close-22',
        category: 'delegation',
      },
      {
        title: 'New maintenance request assigned',
        message: 'A new maintenance request has been assigned to you at 8 River Road — Plumbing leak reported.',
        type: 'info' as const,
        link: '/properties/river-road-8',
        category: 'maintenance',
      },
      {
        title: 'Owner updated property details',
        message: 'The owner of 5 Oak Lane has updated the property access instructions. Review the changes.',
        type: 'info' as const,
        link: '/properties/oak-lane-5',
        category: 'property',
      },
    ];
    ```

    6. For each notification, check if one with the same `title + userId + tenantId` combination already exists (idempotency guard). Skip if found, insert if not.
    7. Use `createId()` from `@shared/lib/id` (existing project pattern) for notification IDs.
    8. Set `read: false`, `createdAt: new Date()`, and appropriate `deliveryStatus: 'SEED'`.
    9. Log a summary: `Seeded N new notification records (M already existed).`

    **Design decisions:**
    - The `link` paths use placeholder property slugs (e.g., `/properties/palm-avenue-14`) rather than real property IDs. This is intentional — the deep-link test exercises the URL parsing + workspace switching logic, not property page rendering. The NotificationLink component's `inferWorkspaceTarget` parses `/properties/` patterns regardless of whether the property exists.
    - The `userId` is sourced from a real resident user in the soralia tenant, so the notifications appear on that user's notifications page.
    - Idempotency uses `title + userId + tenantId` as a compound key — simple and sufficient for a seed script.
    - Delivery status set to `'SEED'` to distinguish seed records from real notification deliveries.

    **Run command:** `npx tsx scripts/seed-notifications.ts`

    The script does NOT import from or modify the existing seed orchestrator (`scripts/seed-drizzle.ts`) — it's a standalone utility for workspace-specific testing. It can be run independently after the main seed.
