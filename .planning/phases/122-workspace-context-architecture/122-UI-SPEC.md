## Copywriting Contract

### Global Vocabulary

| Term            | Use (Approved)      | Avoid (Rejected)   | Source                                |
| --------------- | ------------------- | ------------------ | ------------------------------------- |
| Workspace label | "Current Workspace" | "Working As"       | CONTEXT D-05                          |
| Switching verb  | "Switch to"         | "Become", "Act as" | D-05 (user changes context, not self) |
| Top-level node  | "My Account"        | "My Workspaces"    | D-04 hierarchy model                  |
| Switch notify   | "Now viewing"       | "Logged in as"     | D-07 + switchWorkspace() toast        |

### Per-Surface Copy

| Element                                           | Copy                                                                                                                       |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Primary CTA — Empty state (accept delegation)** | "Accept a delegation invitation"                                                                                           |
| **Primary CTA — Empty state (marketplace)**       | "Browse the Marketplace"                                                                                                   |
| **Primary CTA — Empty state (learn)**             | "Learn how property delegation works"                                                                                      |
| **Empty state heading**                           | "Welcome to Agent Workspace"                                                                                               |
| **Empty state body**                              | "You don't currently manage any delegated properties." + next steps list (3 items above) — exact copy locked in D-12       |
| **Error state — resolve failure**                 | "We couldn't switch workspaces. The delegation may have expired or been revoked. Try again or pick a different workspace." |
| **Error state — registry miss**                   | "Workspace not available. This workspace type may be disabled for your tenant. Contact your administrator."                |
| **Deep-link toast (success)**                     | "Now viewing: {workspace.label}" (e.g. "Now viewing: 14 Palm Avenue")                                                      |
| **Deep-link toast (failed auto-switch)**          | "This link opens a workspace you can't access. You're still in {current.label}."                                           |
| **Destructive — Owner revokes delegation**        | "Revoke Delegation — {delegatee} will lose access to {property} immediately. This cannot be undone."                       |
| **Destructive — Owner suspends access**           | "Suspend Agent Access — {agent} will be blocked from {workspace} until reinstated."                                        |
| **Selector search placeholder**                   | "Search workspaces…"                                                                                                       |
| **Selector empty-search**                         | "No workspaces match \"{query}\"."                                                                                         |
| **Recent group label**                            | "Recent"                                                                                                                   |
| **Pinned group label**                            | "Pinned"                                                                                                                   |
| **All group label**                               | "All workspaces"                                                                                                           |

### Copywriting Rules (lock for the checker)

1. Never use identity language ("Working As", "Logged in as", "Become {name}"). The user is not assuming an identity — they switch operational context (D-05 binding).
2. The deep-link toast is the only place a workspace name appears as the **object** of a sentence; everywhere else it is a label or selectable row.
3. Empty-state CTAs verb-first ("Accept", "Browse", "Learn") — same imperative convention as Phase 45 merits CTAs ("Record Entry").
4. Destructive dialogs name the affected entity (`{delegatee}`, `{property}`, `{workspace}`) and include the irreversibility clause ("cannot be undone") consistent with Phase 45 destructive contract.

## Interaction Contract

### Atomic Workspace Switch (ADDENDUM-023 C-01 — immutable, replace-only)

The visible transition has 5 ordered phases. **No partial state is ever rendered.**

| Step | Visible State                                                    | Approx Duration | Element                                 |
| ---- | ---------------------------------------------------------------- | --------------- | --------------------------------------- |
| 1    | User clicks target workspace row in selector                     | 0ms             | Row highlight (accent bar)              |
| 2    | Selector popover closes via radix `onOpenChange(false)`          | ~150ms          | Popover fade-out                        |
| 3    | `switchWorkspace()` resolves target (async)                      | network-bound   | Top-loading bar appears (`LoadingBar`)  |
| 4    | Context replaced **atomically** (single setState, no in-between) | 1 frame         | Navigation skeleton shimmer (300ms max) |
| 5    | Target route rendered + deep-link toast fires                    | post-render     | Sonner toast (4s auto-dismiss)          |

If resolve fails between steps 3 and 4, the user **stays in the prior workspace** — no half-context is ever set. The toast for failure shows under "Copywriting Contract → Error state — resolve failure".

### Search / Recent / Pinned / All (D-10 — VS Code pattern)

| Group  | Order              | Source                                                    | Max rows shown                  |
| ------ | ------------------ | --------------------------------------------------------- | ------------------------------- |
| Recent | most-recent-first  | client Zustand store, last 5                              | 5                               |
| Pinned | user-pinned order  | client Zustand store, user-managed                        | unlimited (scroll)              |
| All    | registry hierarchy | `WorkspaceRegistry.getEnabledDefinitions()` + delegations | unlimited (virtualised if >100) |

**Search** filters across Recent + Pinned + All simultaneously and hides the group headers when active. Empty-search result shows the "Selector empty-search" copy above.

**Virtualisation:** if All-workspaces exceeds 100 rows, render with a windowed list (`@tanstack/react-virtual`, already available via TanStack ecosystem). Below 100, plain DOM rows.

### Hierarchical Tree Behaviour (D-04)

```
My Account
├── Personal              (always present)
├── Provider              (only if user is a provider)
│     ├── Dashboard        -> /provider/dashboard
│     ├── Marketplace      -> /provider/marketplace
│     └── Delegated Properties
│            ├── 14 Palm Avenue   -> /properties/{id}
│            └── ...
└── Owner                  (only if user owns property)
      ├── My Properties
      ├── Delegations
      └── Audit
AUTOMATION  (registered, hidden from selector until Phase 113+ — D-11)
```

- Chevrons expand/collapse Provider and Owner subtrees. State persists in `localStorage` (`soralia:workspace-tree-expanded`). Default: collapsed.
- Delegated Properties is always expanded when Provider subtree opens (most-used path).
- Property rows show property name + delegator (12px label, `text-gray-500`) — identity-before-scope is the universal pattern.

### Automatic Workspace Switch on Notification Deep Link (D-07)

| Trigger                               | Behaviour                                                                                           |
| ------------------------------------- | --------------------------------------------------------------------------------------------------- |
| In-app notification click             | `switchWorkspace(target)` fires → navigate to resource → toast ("Now viewing: {workspace.label}")   |
| Deep link from external (email/SMS)   | Middleware resolves token → sets hint header → AppShell detects hint → calls `switchWorkspace` once |
| Target inaccessible (revoked/expired) | Stay in current workspace, show error toast, do not navigate                                        |
| Already in target workspace           | No toast; just navigate to the resource                                                             |

The hint header is **read-once** by `AppShell`; it is not a URL parameter (ADDENDUM-023 C-02 — URLs are resource-only).

### Keyboard Navigation (a11y)

| Key               | Action                                              |
| ----------------- | --------------------------------------------------- |
| `Cmd/Ctrl+K`      | Open workspace selector (global shortcut)           |
| `ArrowDown/Up`    | Move active row within selector                     |
| `ArrowRight/Left` | Expand / collapse subtree at active row             |
| `Enter`           | Switch to active workspace (close popover + switch) |
| `Esc`             | Close selector without switching                    |
| `/` (in selector) | Focus search input                                  |
| `Tab`             | Standard DOM order — no trap; selector is non-modal |

The selector is a **popover**, not a modal — background tab order is preserved (radix `Popover` semantics). Focus moves to search input on open; `Esc` returns focus to the trigger button.

## Workspace Scope Panel — Content Contract (D-13)

> URLs are resource-only (C-02). The scope panel is the **only** place workspace identity is shown; it is **not** echoed in breadcrumbs or URL slugs.

### Personal

```

──────────────────────────
```

### Property (delegated — D-13 example)

```
──────────────────────────

{property.address}
Delegated by: {delegator.displayName}
```

### Owner

```

──────────────────────────
Owner
{owner.displayName}
Properties: {N owned} | Delegations: {N active}

Expires: Never
```

### Automation (registered, disabled — D-11)

Render the row in the registry only; **the scope panel never renders for Automation** this phase. When enabled (Phase 113+), contract will be amended.

### Field Rules (lock for the checker)

| Field        | Required               | Source field                                                      | Missing behaviour                            |
| ------------ | ---------------------- | ----------------------------------------------------------------- | -------------------------------------------- |
| Type label   | yes                    | `WorkspaceDefinition.label`                                       | Render the `workspaceType` enum literal      |
| Name         | yes                    | `workspaceType`-derived (user name / provider name / address)     | Render "Unnamed workspace" + log warn (Pino) |
| Scope line   | yes                    | `scope.propertyId \| providerId \| ownerId` resolved into a label | Hide scope line if scope unset (Personal)    |
| Delegated by | Provider/Property only | resolved from `Delegation` model                                  | "Direct access" if no delegation (rare)      |
| Expires      | Provider/Property only | `Delegation.expiresAt`                                            | "Never" if null                              |
| Permissions  | yes                    | `WorkspaceContext.permissions[]` joined by comma                  | "—No permissions—" if empty (rare, log warn) |

## Workspace-Specific Actions (D-14)

Actions are **contextual, not global**. Each workspace type exposes only the actions in its `WorkspaceDefinition.actions[]` (C-05 — registry-driven, not hardcoded). Rendered in the scope panel's action menu.

| Workspace | Actions                                            | Trigger UX                                                                |
| --------- | -------------------------------------------------- | ------------------------------------------------------------------------- |
| Personal  | Profile, Settings                                  | Inline links in scope panel                                               |
| Provider  | Marketplace, Bookings, Staff                       | Action menu (overflow `…` button)                                         |
| Property  | Create Maintenance, Message Owner, Upload Document | Action menu                                                               |
| Owner     | Create Delegation, Review Audit, Suspend Access    | Action menu; destructive items render in red-600 with confirmation dialog |

No flat "Quick Actions" panel spans workspaces (D-14 — explicit constraint). The existing global `SpaceLauncher`/`MobileSpaceBar` focus-space nav is unaffected — workspace actions supplement nav, they do not replace it.

## Binding Constraint → Contract Mapping (ADDENDUM-023)

| Constraint                                                | Contract Enforcement Point                                                                                                           |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| C-01 Immutable WorkspaceContext                           | Atomic switch transition has no partial render state (5-step Interaction Contract)                                                   |
| C-02 URLs resource-only                                   | Scope panel is the only workspace-identity surface; no breadcrumbs/URL state; middleware hint header is read-once                    |
| C-03 WorkspaceContext is lightweight (scope pointer only) | Scope panel renders only the 6 allowed fields; no domain data, no tasks/messages widgets in panel                                    |
| C-04 No Role-branching for workspace behaviour            | Workspace-type-driven rendering via `WorkspaceDefinition`; selector visible rows driven by registry + delegations, not `Role` checks |
| C-05 Registry required before selector                    | P1a-1 (WorkspaceRegistry) is a hard dependency of P1a-4 (selector); UI-SPEC presumes registry exists                                 |
