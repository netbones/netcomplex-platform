## Trust Boundaries

| Boundary                       | Description                                                                                                                                                                                  |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| session → WorkspaceContext     | WorkspaceContext is derived from the Better Auth session + RLS-gated delegation rows. The boundary is enforced server-side at /api/delegations (withTenant + RLS — see STATE [Phase 43-04]). |
| WorkspaceContext ↔ GateContext | Two orthogonal hooks coexist; neither derives the other. WorkspaceSwitching must NOT change GateContext's role/flags (C-04).                                                                 |

| Threat ID | Category               | Component                                                | Severity | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------- | ---------------------- | -------------------------------------------------------- | -------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-122-04  | Information Disclosure | resolveWorkspaceContext / tenant boundary                | high     | mitigate    | All delegation data flowing into WorkspaceContext comes from `useDelegations()` → `GET /api/delegations`, which is tenant-isolated server-side (withTenant + RLS per Phase 43-04). Tenant-A users physically cannot receive tenant-B delegations; the resolver only projects already-authorized rows into a context object. P-05 guard test asserts no domain PII keys leak into the serialized context. Verified by resolver tests asserting the only sources are the session + RLS-gated delegations. |
| T-122-05  | Elevation of Privilege | PROPERTY resolver / permissions                          | high     | mitigate    | `permissions` on a PROPERTY WorkspaceContext come exclusively from `delegation.permissions` (server-authoritative). The resolver NEVER invents or escalates permissions; it throws `registry_miss`/`revoked`/`forbidden` on any unauthorized path. Switching workspace cannot grant a capability the user lacks via the delegation.
