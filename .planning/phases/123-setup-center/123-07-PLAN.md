# Plan 123-07: Migration & Cleanup

## Goal

Migrate all existing onboarding data from ad-hoc `onboarding_step_N` Setting keys to the new structured `TenantSetup` / `SetupMission` / `SetupSetting` models. Remove the old wizard code and redirect old URLs. This is the final wave — the old wizard is gone and the Setup Center is the canonical experience.

## Pre-flight

This phase executes inside `phase-123-setup-center` worktree. Verify:

```bash
wt list | grep phase-123-setup-center  # must show active worktree
[ -f .env ] || cp ../soralia-village/.env .  # .env must exist
```

**CRITICAL:** Before running migration, take a database backup or snapshot. This migration rewrites tenant onboarding data.

## Tasks

### Task 1: Data migration script

<files>scripts/migrate-onboarding-to-setup-center.ts</files>
<action>

Create `scripts/migrate-onboarding-to-setup-center.ts`:

```
1. Dry-run mode (--dry-run flag): prints what would happen, doesn't write
2. Real mode: for each tenant with onboarding_step_* Setting keys:
   a. SELECT all Setting rows WHERE key LIKE 'onboarding_step_%' AND tenantId = ?
   b. Create TenantSetup record (skip if already exists — idempotent)
   c. For each step key:
      - Parse value as JSON
      - Map step data to SetupMission completion states:
        step_1 (branding) → missions: launch.name, launch.branding
        step_2 (modules) → missions: configure.* (one per module)
        step_3 (facilities) → missions: configure.facilities
        step_4 (maintenance) → missions: configure.maintenance_categories
        step_5 (pages) → missions: configure.page_visibility
        step_6 (invites) → missions: populate.invite_board
        step_7 (launch) → missions: launch.community_launched
      - Create SetupMission records for each
      - Create SetupSetting records from step data (key = setting key, value = parsed JSON)
   d. Calculate completionPercent from completed vs total missions
   e. Set launchedAt if onboarding_completed = 'true'
   f. Move old onboarding_step_* Setting keys to DEPRECATED prefix:
      UPDATE settings SET key = 'deprecated_onboarding_step_N' WHERE key = 'onboarding_step_N'
   g. Move onboarding_completed → deprecated_onboarding_completed
3. Log summary: tenants processed, missions created, settings migrated
```

Use Drizzle for all queries. Run inside a transaction per tenant for atomicity. Handle errors per-tenant (one bad tenant doesn't block others).

</action>
<verify>Dry-run shows correct migration plan. Real run creates correct records. Running twice produces no duplicates (idempotent).</verify>
<done>Data migration with dry-run support and idempotency</done>
