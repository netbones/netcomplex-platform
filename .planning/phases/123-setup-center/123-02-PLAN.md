# Plan 123-02: Setup Center API Layer

## Goal

Build the API routes that power the Setup Center — progress retrieval, mission completion toggling, setup settings CRUD, and automatic initialization on tenant creation.

## Pre-flight

This phase executes inside `phase-123-setup-center` worktree. Verify:

```bash
wt list | grep phase-123-setup-center  # must show active worktree
[ -f .env ] || cp ../soralia-village/.env .  # .env must exist
```

## Tasks

### Task 1: Tenant-scoped progress API

<files>src/app/api/platform/setup/route.ts</files>
<action>

Create `GET /api/platform/setup`:

- Accept `?tenantId=<id>` query param
- Verify caller is the tenant owner (user.id === tenant.ownerId) OR has `tenant_admin` role — use a tenant-scoped guard, NOT `requirePlatformAdmin()`
- Query `TenantSetup` table with Drizzle, join `SetupMission` records
- Group missions by `section`, compute `completionPercent` from `isCompleted` ratio
- Return `apiSuccess({ setup: { ...tenantSetup, missions: { launch: [...], populate: [...], configure: [...], grow: [...] } } })`

</action>
<verify>`curl http://localhost:3000/api/platform/setup?tenantId=test-id` returns expected shape for an authenticated tenant owner</verify>
<done>Progress API returns grouped missions with percentage</done>

### Task 2: Mission completion API

<files>src/app/api/platform/setup/missions/route.ts</files>
<action>

Create `PATCH /api/platform/setup/missions`:

- Accept `{ tenantId, missionKey, isCompleted }` body, validated with Zod
- Tenant-scoped auth: user must be tenant owner or `tenant_admin`
- Toggle `SetupMission.isCompleted`, set `completedAt` to now if completing
- Recalculate all `isCompleted` → `completionPercent` on the parent `TenantSetup`
- Auto-mark parent section as completed if all its required missions are done
- Return `apiSuccess({ mission, completionPercent })`

</action>
<verify>PATCH toggles a mission, recomputes percent, returns updated state. Non-owner gets 403. No session gets 401.</verify>
<done>Mission completion toggles with percentage recalculation</done>

### Task 3: Setup settings CRUD API

<files>src/app/api/platform/setup/settings/route.ts</files>
<action>

Create `GET /api/platform/setup/settings?tenantId=<id>` and `PATCH /api/platform/setup/settings`:

- `GET` returns all `SetupSetting` records for a tenant as `{ settings: Record<string, Json> }`
- `PATCH` accepts `{ tenantId, key, value }` — upserts a single setting. Tenant-scoped auth.
- Use `apiSuccess`/`apiError` envelopes, Zod validation for request body

</action>
<verify>GET returns existing settings, PATCH creates/updates a setting and returns it. Non-owner gets 403.</verify>
<done>Setup settings CRUD with tenant-scoped auth</done>

### Task 4: Initialize TenantSetup on tenant creation

<files>src/entities/setup/api/init-setup.ts</files>
<action>

Create `initTenantSetup(tenantId, tier)`:

- Creates a `TenantSetup` record with `completionPercent: 0`
- Seeds default `SetupMission` records from `DEFAULT_MISSIONS` catalog in constants.ts
- Filters missions by tier (don't seed premium-only missions for foundation tier)
- Called from `POST /api/platform/tenants` route after tenant creation succeeds

Update `src/app/api/platform/tenants/route.ts` to call `initTenantSetup()` after the user + tenant creation transaction completes.

</action>
<verify>Creating a new tenant via the signup API also creates TenantSetup + mission records. Verify via `GET /api/platform/setup` response.</verify>
<done>Tenant creation seeds Setup Center data</done>
