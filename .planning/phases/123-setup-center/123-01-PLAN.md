# Plan 123-01: Schema & Entity Foundation

## Goal

Add the 3 new Prisma models (`TenantSetup`, `SetupMission`, `SetupSetting`) that replace the ad-hoc `onboarding_step_N` Setting keys with structured progress tracking. Generate Drizzle schemas and create the FSD entity layer.

## Pre-flight

This phase executes inside `phase-123-setup-center` worktree. Verify:

```bash
wt list | grep phase-123-setup-center  # must show active worktree
[ -f .env ] || cp ../soralia-village/.env .  # .env must exist
```

## Tasks

### Task 1: Add Prisma models

<files>prisma/schema.prisma</files>
<action>Add `TenantSetup`, `SetupMission`, and `SetupSetting` models after the existing `Setting` model block.</action>

- `TenantSetup` has `id`, `tenantId` (unique FK), `completionPercent` (int, default 0), `completedSections` (String[] default []), `launchedAt` (DateTime?), `lastViewedAt`, timestamps, `deletedAt`
- `SetupMission` has `id`, `tenantSetupId` (FK cascade), `section`, `missionKey`, `title`, `description?`, `isRequired` (default false), `isCompleted` (default false), `completedAt?`, `sortOrder` (default 0), `metadata?` (Json), timestamps. `@@unique([tenantSetupId, missionKey])`, `@@index([tenantSetupId, section])`
- `SetupSetting` has `id`, `tenantSetupId` (FK cascade), `key` (String), `value` (Json), timestamps. `@@unique([tenantSetupId, key])`
- Use `@relation` with named relations, `onDelete: Cascade` on both child models
- Use `cuid()` for all IDs

<verify>`npx prisma validate` passes with no schema errors</verify>
<done>Prisma schema valid</done>

### Task 4: Create FSD entity layer

<files>src/entities/setup/</files>
<action>Create `src/entities/setup/` directory with:

- **`types.ts`** — TypeScript interfaces: `TenantSetup`, `SetupMission`, `SetupSetting`, `SetupSection` (union: `'launch' | 'populate' | 'configure' | 'grow'`), `MissionRef` (for the recommendation engine)
- **`constants.ts`** — `SECTIONS` array (`[{ key: 'launch', labelKey: '...', isRequired: true }, ...]`), `DEFAULT_MISSIONS` catalog (all missions keyed by `MissionRef` with `section`, `title`, `description`, `isRequired`, `metadata`), `REQUIRED_LAUNCH_MISSIONS` (keys that must be completed before `launchedAt` can be set)
- **`schema.ts`** — Zod validators: `setupMissionSchema`, `setupSettingSchema`, `setupProgressSchema` (for API request validation)
- **`index.ts`** — barrel re-exports of all public types, constants, and schemas

</action>
