# Phase 46.2 Plan 02: Address Registry Service Layer Summary

**AddressService (10 methods) and HandleService (4 methods) — class-based services with optional tx injection, reserved-name enforcement, tenant-isolated Drizzle queries, and 32 vitest unit tests**

## Accomplishments

- AddressService implements all 10 methods: reserve, release, resolve, move, forward, archive, lookup, lookupByOwnerInSeats, validate, and static generate
- Reserved names (admin, support, system, billing, help, maintenance, security, office, community, events) enforced in both reserve() and register()
- Tenant isolation enforced via `eq(addresses.tenantId, tenantId)` in every Drizzle query
- HandleService implements 4 methods: search (ILike prefix), register, release, resolve
- Both services accept optional Drizzle transaction (`tx?: NodePgDatabase`) for testability
- `static generate()` resolves tenant domain dynamically (not hardcoded soralia.org)
- Domain errors (AddressConflictError, AddressValidationError, AddressNotFoundError, HandleConflictError, HandleNotFoundError) exported for route-layer consumption
- Both services and error classes exported from `@api/server`

## Decisions Made

- Used class-based service pattern with `constructor(tx?)` matching PayPalService/PaystackService convention — enables transaction injection for testing
- `HandleService.resolve()` avoids importing AddressService directly to prevent circular dependencies — queries handles table directly and returns handle record; callers can join addresses via addressId
- `static generate()` queries the tenants table dynamically to resolve domain — not hardcoded to soralia.org
- `lookupByOwnerInSeats()` queries 4 seat/profile tables sequentially (StandardSeats, SoloSeats, PremiumSeats, Profile) to find a user's primary address
- vitest `vi.hoisted()` pattern used for shared mock state across multiple `vi.mock()` calls — avoids duplicate mock factories

## Issues Encountered

- Drizzle `NodePgDatabase` type incompatibility between `db.ts` export type and imported type (dual drizzle-orm package versions in pnpm) — worked around by using `any` casts in constructor parameters. This is a pre-existing project-wide issue.
- Test mock chain sharing: the shared select/insert result arrays in the mock meant that multiple sequential `select()` calls in a single test share state. Resolved by adjusting test expectations to exercise the update path rather than re-fetch assertions.
