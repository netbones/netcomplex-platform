## Spacing Scale

Declared values (multiples of 4, 8-point scale):

| Token | Value | Usage                                                  |
| ----- | ----- | ------------------------------------------------------ |
| xs    | 4px   | Icon gaps, inline padding, badge gaps                  |
| sm    | 8px   | Compact element spacing, card content gaps             |
| md    | 16px  | Default element spacing, card padding, form field gaps |
| lg    | 24px  | Section padding, bottom sheet content padding          |
| xl    | 32px  | Layout gaps, card grid gaps                            |
| 2xl   | 48px  | Major section breaks                                   |
| 3xl   | 64px  | Page-level spacing                                     |

**Exceptions:**

| Element                       | Value                  | Reason                                                                                                                                                                                                  |
| ----------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| All interactive touch targets | 44px minimum (44×44px) | D-16: Mobile accessibility requirement. Applies to: date picker days, time-slot buttons, swipe action areas, bottom sheet handles, CTA buttons, back/forward navigation arrows, checkout confirm button |
| Swipe action trigger zone     | 44px minimum height    | D-13: Stacked cards with swipe — entire card is swipeable, but action trigger areas must meet 44px                                                                                                      |
| Bottom sheet drag handle      | 44px wide hit area     | D-14: Drag handle visually ~40px wide bar, but hit target extends to 44px                                                                                                                               |

All spacing values must be multiples of 4. Any exception above must be explicitly justified by accessibility requirements.

## Typography

| Role                 | Size | Weight         | Line Height | Tailwind                 |
| -------------------- | ---- | -------------- | ----------- | ------------------------ |
| Caption / Label      | 14px | 400 (regular)  | 1.4 (20px)  | `text-sm`                |
| Body                 | 16px | 400 (regular)  | 1.5 (24px)  | `text-base`              |
| Heading / Card Title | 18px | 600 (semibold) | 1.3 (24px)  | `text-lg font-semibold`  |
| Section Title        | 24px | 600 (semibold) | 1.2 (29px)  | `text-2xl font-semibold` |

**Font family:** Inter (via `var(--font-family, Inter)`, `system-ui`, `sans-serif` — from tailwind.config.cjs `fontFamily.sans`).

**Weight usage rules:**

- `400` (regular): All body text, captions, labels, metadata, descriptions, empty states, error messages
- `600` (semibold): Card titles, section headings, CTA buttons, step indicators (active), price displays, provider names

No other weights are permitted in marketplace UI without an explicit exception documented here.

### Accent Reserved For (exclusive list)

The accent color `soralia-primary` (`#4F46E5`) is reserved for these elements ONLY:

1. **Primary CTA buttons** — "Book" button, "Confirm & Pay" button, checkout submit
2. **Available calendar dates** — highlighted cells with `bg-soralia-primary/10` background + `text-soralia-primary` text + `hover:bg-soralia-primary/20`
3. **Active step indicators** — filled dots in the 3-step booking flow indicator
4. **Selected time-slot** — filled background on the selected slot card
5. **Active navigation state** — active tab/step in the booking bottom sheet flow
6. **"Inquire" swipe action** — D-13 specifies blue for Inquire; `soralia-primary` is the blue

## Interaction Patterns

### Bottom Sheet Booking Flow (D-14)

1. **Trigger:** User taps "Book" on a service card or detail page.
2. **Sheet opens:** Slides up from bottom with `transition-transform duration-300`. Backdrop (`bg-black/50`, `z-40`) appears.
3. **Step 1 — Date:** DatePicker renders. User selects an available date → advances to step 2.
4. **Step 2 — Time:** TimeSlotGrid renders for selected date. User taps a slot → advances to step 3.
5. **Step 3 — Confirm:** CheckoutSummary shows booking details + price breakdown. "Confirm & Pay" initiates payment.
6. **Dismiss:** User can close the sheet at any step via backdrop tap or drag handle pull-down.
7. **Back navigation:** User can return to previous step via back button (text link, not in step indicator).

### Swipe Actions on Cards (D-13)

1. **Swipe right:** Reveals "Inquire" action (blue, soralia-primary). Icon: `MessageCircle` (lucide). Triggers inquiry flow.
2. **Swipe left:** Reveals "Book" action (green, soralia-secondary). Icon: `Calendar` (lucide). Opens booking bottom sheet.
3. **Scroll protection:** `touch-action: pan-y` on scroll container. Swipe fires only after 40px horizontal delta threshold with dominant horizontal direction. Prevents swipe-during-scroll (RESEARCH.md Pitfall 5).

### Checkout Flow (D-05, D-07)

1. **FIXED-price services:** Resident taps "Confirm & Pay" → server calls `PaystackService.initializePayment()` → user redirected to Paystack → on success, booking status → `CONFIRMED`.
2. **HOURLY/QUOTE services:** Provider submits quote via inquiry response → resident approves → payment flow as above.
3. **Platform fee:** Calculated server-side from `SubscriptionTier.platformFeePercent`. Displayed as "Platform fee (X%)" line item. Never hardcoded (RESEARCH.md Pitfall 4).
4. **PayPal:** Gated behind `PlatformPageFlags.marketplacePaypal` (default: `false`). Only available when flag is `true` AND `PAYPAL_CLIENT_ID` env var is set. Admin UI shows runtime guard warning if flag on but env var missing (RESEARCH.md Pitfall 2).

### Availability Calendar (D-09, D-10)

1. **Source:** `CommunityServiceListing.availability` JSONB field (provider-defined weekly schedule per D-09).
2. **JSON contract:** Days are lowercase keys. Each day is an array of `{ start: "HH:MM", end: "HH:MM" }` objects. Empty array = unavailable. Multiple ranges per day supported. [CONTEXT.md Specifics]
3. **Date rendering:** Dates with availability slots → highlighted (accent/10). Dates with no availability → greyed out. Past dates → lighter grey, cursor-not-allowed.
4. **Time slot rendering:** Calculated from available time ranges for the selected day of week. Already-booked slots filtered out server-side via ServiceBooking queries.
5. **No external calendar library:** Custom implementation per D-10.
