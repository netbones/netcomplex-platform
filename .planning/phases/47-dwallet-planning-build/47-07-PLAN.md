PAGE STRUCTURE (following UI-SPEC.md Surface 3):

**PAGE HEADER:**

- Title: "My dWallet" with Wallet icon
- Available Value: R {balance} (28px semibold, indigo-600)
- Pending Distribution: R {amount} (16px, slate-600)
- Est. next distribution: {date} (text-sm text-slate-400)
- Action buttons: [Export] [•••] (overflow menu with "Download Annual Statement" and "Delete My Data")

**TAB BAR:** 5 tabs — Overview | Activity | Impact | Consents | Payouts

- Active tab: indigo-600 underline + font-semibold
- Inactive tabs: slate-500, hover:slate-700
- Use URL hash or state for tab navigation (e.g., ?tab=activity)
- Default tab: Overview

**TAB 1 — OVERVIEW:**

- Available Value display + Pending Distribution + Lifetime stats
- Earnings Breakdown Card (simplified — full component with per-stream revenue breakdown)
- Community Impact Card: 2×2 stat grid (Active Streams, Participating Residents, Total Pool, Your Est. Share)
- Revenue stream summary cards
- Quick actions: "Request Payout", "Export My Data", "Download Annual Statement"
- Last 5 community activities (link to Activity tab)

**TAB 2 — ACTIVITY:**

- Full paginated activity history table
- Columns: Date, Type (badge with no-banking colors: Value Earned=indigo-600, Value Used=slate-600, Value Rolled=slate-400, Adjustment=gray-400), Source, Amount (signed with color), Value Before, Value After
- Filter: type dropdown + date range pickers
- Sort: newest first default, clickable column headers
- Pagination: page numbers or load more

**TAB 3 — IMPACT:**
Per UI-SPEC §Tab 3 — all metrics derivable from the actual financial model:

- Total Resident Share Pool: large stat "R [derived] — Total Resident Share Pool (Current Period)"
- Participating Residents: "X residents currently opted in"
- Your Estimated Share: "R [derived] (1/[count] of community total)"
- Active Revenue Streams: "X of 8 revenue streams generating value this period"
- Community Benefit Fund card: distinct visual treatment (slate bg, info icon) showing:
  - "This fund supports projects that benefit all residents..."
  - Current Balance, Unclaimed Transfers (from expired rewards after 12 months), Next Allocation
  - [View Community Projects →] link
  - Clearly marked "not your personal balance"
- Revenue Stream Contribution Breakdown: simple per-stream list with contribution percentages
- Empty state: "No impact data yet..."

**TAB 4 — CONSENTS:**
Per UI-SPEC §Tab 4:

- Master toggle at top: "Resident Data Share Program [ON/OFF]" — single program-level opt-in for payout eligibility. Description: "Share in platform revenue earned by the community. Your share = total pool ÷ all participants."
- Per-stream toggles below — each controls DATA USAGE only:
  - Stream label + description: "Controls whether your anonymised data is used for [purpose]. Does not affect your Resident Data Share rewards."
  - Toggle switch (ON=indigo-600, OFF=slate-200)
  - Date line: "Granted 15 Jun 2026" or "Revoked 01 Apr 2026 (paused)"
  - No estimated rand values on per-stream toggles
- Info text: "Revoking consent stops future data usage for that stream. Past value earned is not affected."
- Audit disclaimer: "All consent changes are logged and retained for 5 years per Schedule G4."

**TAB 5 — PAYOUTS:**

- Payout form: amount field (pre-filled to current balance, editable), method "Bank Transfer" (display-only)
- "Request Payout" button disabled if balance < R50 with tooltip
- Payout history table: Date Requested, Amount, Status (badge), Processed Date, Notes
- Payout Compliance Notes (sidebar/info block):
  - R50 minimum threshold, monthly or on-request (Schedule G G3)
  - Unclaimed rewards → CBF after 12 months
  - Pro-rata: reward = pool ÷ participants

**STATES:**

- Loading: LoadingSkeleton for each tab's content
- Empty wallet: Show empty states per tab (per UI-SPEC §Empty State Copy lines 145-153)
- Error: ErrorBoundary wrapping the entire page with "Could not load dWallet" fallback

**DATA FETCHING:**

- Use useWallet() hook for Overview/Consents tab data
- Direct fetch for Activity (paginated), Impact (aggregated), Payouts (history)
- TanStack Query stale times: community value 30s, activity 2min, consent 1min, impact 5min, payouts 30s

DO NOT: use banking/fintech terminology — labels use "Community Value" not "Balance", "Value Earned" not "Income", "Community Activity" not "Transactions" (per UI-SPEC §Copywriting Contract). Do not hardcode stream names — fetch from GET /streams. Do not use green for gains or red for losses. Follow the indigo/slate color scheme per the UI-SPEC Color contract.
