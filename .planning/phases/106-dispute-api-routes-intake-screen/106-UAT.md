## Tests

### 1. Create a New Dispute

expected: The admin dispute list page shows a "File a Dispute" button. Creating a dispute produces a DRAFT with a DSP-YYYY-NNNN reference number and a 24-hour cooling-off countdown.
result: pending

### 2. View and Filter the Dispute List

expected: /admin/disputes shows a table of disputes with status, category, and severity badges. You can search by reference number or title, sort by columns, and filter by status.
result: pending

### 3. View a Dispute Detail Page

expected: /admin/disputes/[id] shows the full dispute in a two-column layout: timeline events on the left, AI panel + cooling-off timer + actions + mediation thread on the right.
result: pending

### 4. Update Dispute Details

expected: Editing dispute fields (title, description, category) persists changes and the updated timestamp refreshes. Invalid status transitions show an appropriate error.
result: pending

### 5. Submit a Dispute After Cooling-Off

expected: While the cooling-off timer is active, the Submit button is disabled. After 24 hours expire, the timer shows "Ready to Submit." Submitting transitions the dispute from DRAFT to SUBMITTED and logs a SUBMITTED event in the timeline.
result: pending

### 6. Post Mediation Messages

expected: On the dispute detail page, the mediation thread allows posting messages. As a resident, you can post messages and see non-internal messages from others. As a moderator (BOARD/ADMIN), you can post internal notes (amber badge) that are only visible to other moderators.
result: pending

### 7. Upload Evidence Files

expected: The evidence upload zone on the detail page accepts drag-and-drop of image files (JPEG, PNG, GIF, WebP) up to 2MB each. Uploaded files appear in the preview grid with thumbnails and can be removed individually.
result: pending

### 8. Assign a Moderator (BOARD/ADMIN)

expected: As a BOARD or ADMIN user, the action bar shows an "Assign Moderator" button. Clicking it opens a modal to search for and select a user. The assignment creates an ASSIGNED event in the timeline.
result: pending

### 9. Issue a Formal Ruling (BOARD/ADMIN)

expected: As a BOARD or ADMIN user, the action bar shows "Issue Ruling." Clicking opens a form to enter the ruling text. The ruling transitions the dispute to FORMAL_RULING status with a RULING_ISSUED timeline event.
result: pending

### 10. AI Intake Screen — Frivolity Check

expected: The AI frivolity check panel on the detail page shows a "Check for Frivolity" button. Clicking it analyzes the dispute description and displays a tone score (green/amber/red), a frivolity indicator, a suggested category, and a de-escalation tip. When AI is unavailable, a message says screening is temporarily unavailable.
result: pending

### 11. Cooling-Off Timer Countdown

expected: For DRAFT disputes, the detail page shows a live countdown (HHh MMm SSs) that decrements every second. When the timer reaches zero, it displays "Ready to Submit" and the Submit button becomes active.
result: pending

### 12. CSOS Export

expected: The CSOS export button downloads a JSON file containing the full dispute event log with 6 sections: parties, summary, resolution history, evidence, ruling, and certification. After 3 exports in a day, the button shows a rate-limit warning.
result: pending

### 13. Mediation Thread Real-Time Updates

expected: When two users both have the same dispute detail page open and one posts a mediation message, the other sees the new message appear in their mediation thread automatically without refreshing the page.
result: pending

### 14. Access Control — Resident Cannot See Internal Notes

expected: As a RESIDENT, you can post and view normal mediation messages but never see internal notes (amber-badged BOARD/ADMIN messages). As a BOARD member, you can see both normal and internal messages.
result: pending

### 15. Graceful Degradation — AI Unavailable

expected: When the AI provider is unavailable (NullProvider, quota exhausted, API error), the frivolity check panel shows "AI screening temporarily unavailable — you may proceed without it" rather than crashing or showing an error page.
result: pending

### 16. Role-Based Action Bar Visibility

expected: Different user roles see different action buttons. RESIDENT sees Submit and Withdraw. BOARD sees Submit, Assign Moderator, Issue Ruling, Export CSOS. ADMIN sees all actions including Delete.
result: pending
