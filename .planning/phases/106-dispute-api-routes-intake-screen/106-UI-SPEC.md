# Phase 106 — UI Design Contract

> Visual and interaction contract for dispute API routes and intake screen.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Note

This phase is **API-heavy** — 11 REST route handlers plus the AI intake screen endpoint.
The multi-step intake wizard form is **deferred to Phase 107** per 106-CONTEXT.md.
Phase 106 delivers the admin-facing UI surfaces that consume these new API routes
and the AI frivolity check result display.

**Phase 106 UI surfaces:**

1. **Dispute List Page** (`/admin/disputes`) — table listing all disputes with status/category/severity badges
2. **Dispute Detail Page** (`/admin/disputes/[id]`) — full dispute view with timeline, mediation thread, evidence, actions
3. **AI Frivolity Check Result Panel** — advisory panel showing `toneScore`, `likelyFrivolous`, `suggestedCategory`, `deEscalationTip`
4. **Mediation Thread** — chat-like message list with `isInternal` visibility rules (parties see non-internal; moderators see all)
5. **Evidence Upload** — drag-and-drop file upload with preview, MIME validation, 2MB limit
6. **CSOS Export Trigger** — button/action to export dispute case as JSON (PDF formatting deferred to Phase 108)

## Spacing Scale

Declared values (standard 8-point scale — carried forward from Tailwind defaults
and existing project spacing patterns):

| Token | Value | Usage                                                     |
| ----- | ----- | --------------------------------------------------------- |
| xs    | 4px   | Icon gaps, inline padding between badge segments          |
| sm    | 8px   | Compact element spacing, message bubble gaps              |
| md    | 16px  | Default element spacing, card padding, form field spacing |
| lg    | 24px  | Section padding, card section padding                     |
| xl    | 32px  | Layout gaps between major sections                        |
| 2xl   | 48px  | Major section breaks (e.g., between timeline and thread)  |
| 3xl   | 64px  | Page-level spacing                                        |

Exceptions:

- **Badge internal padding** (inherited from Phase 105):
  - Status badges: `px-2.5 py-0.5` (maps to 10px x / 2px y — slightly off 8pt but intentional for pill shape)
  - Category badges: `px-2 py-0.5` (maps to 8px x / 2px y — on scale)
- **Severity bar height**: `h-2` (8px) — intentional compact indicator
- **Icon-only touch targets**: 44px minimum for interactive icon buttons (accessibility)

## Interaction Contracts

### Mediation Thread

- **Realtime**: Subscribe to Supabase Realtime channel `dispute:{disputeId}` on mount
- **Visibility**: Party users see only `isInternal: false` messages. BOARD/ADMIN/COMMITTEE see all messages (internal notes rendered with amber background + "Internal Note" badge)
- **Scroll**: Auto-scroll to bottom on new message; "New messages" floating button when scrolled up
- **Empty state**: "No messages yet. Messages in the mediation thread will appear here."

### Evidence Upload

- **Drag state**: Dashed border pulses (`border-2 border-dashed border-soralia-primary`) when file dragged over zone
- **Validation errors**: Inline toast via Sonner for MIME type rejection ("PDFs, images, and documents up to 2MB accepted") or size rejection ("File exceeds 2MB limit")
- **Upload progress**: `LoadingSpinner` overlay on individual thumbnail during upload
- **Max files**: 10 per dispute per ADVISORY-017

### AI Frivolity Check

- **Trigger**: "Check Dispute" button in dispute detail or during intake flow (Phase 107)
- **Loading state**: `LoadingSkeleton` with 3 placeholder lines + "Analyzing dispute description..." label
- **Error state**: Inline amber banner: "AI screening is currently unavailable. You can still proceed."
- **Result panel**: Non-persisted — shown above the dispute description. Three sections in a bordered card:
  1. Tone Analysis: horizontal bar with score 0–10, color-coded (green/amber/red)
  2. Likely Frivolous: checkmark (✅) or warning (⚠️) with confidence level
  3. De-escalation Tip: text suggestion in italic
- **Graceful degradation**: API returns 503 → panel shows error state; API returns 429 → shows quota message; both states allow user to proceed

### Cooling-Off Timer

- **Visibility**: Only shown when `status === 'DRAFT'` and `coolingOffEndsAt` is in the future
- **Format**: Countdown timer displaying `HHh MMm SSs remaining`
- **Expired state**: Timer replaced with green "Ready to Submit" banner + enabled Submit button
- **Error state**: 423 response from submit endpoint → inline error with remaining time in seconds

### CSOS Export

- **Button states**: Enabled (0–2 exports today), Disabled with tooltip (3 exports today — "Daily export limit reached")
- **Loading**: `LoadingButton` state while generating
- **Success**: Triggers file download (JSON in Phase 106; PDF in Phase 108)
- **Rate limit error**: Sonner toast with "Export limit reached (3 per day). Try again tomorrow."

## Responsive Behavior

- **Dispute List Table**: Full table on `md+`; card-based list on mobile (`<md`) with status badge + title + severity + date in a stacked layout
- **Dispute Detail**: Two-column on `lg+` (timeline+evidence left, mediation thread right); single-column stacked on mobile/tablet
- **Mediation Thread**: Full-width message bubbles, max-width 80% of container for readability
- **Evidence Upload**: Full-width drop zone; grid of thumbnails collapses from 4 columns (`lg`) → 2 columns (`sm`) → 1 column (`xs`)
- **AI Frivolity Panel**: Full-width below dispute title; stacks vertically on mobile

## Accessibility

- All interactive elements keyboard-navigable (Tab order: dispute list → row → detail → actions → messages → evidence)
- `DisputeStatusBadge` uses semantic color contrast (text-on-tint, meets WCAG AA)
- File upload zone: `role="button"`, `aria-label="Upload evidence files"`, keyboard-activatable (Enter/Space)
- Mediation messages: `role="log"` for live region; `aria-label="Mediation thread messages"`
- Cooling-off timer: `role="timer"`, `aria-live="polite"` for screen reader updates
- Destructive actions: Confirmation dialog with `role="alertdialog"`, focus trapped within dialog
- Loading states: `role="status"` on all loading indicators
- Focus rings: visible on all interactive elements via Tailwind `focus:ring-2 focus:ring-soralia-primary`
