Create the access control entity layer at src/entities/access/:

**types.ts** — Define the canonical access types:

- `AccessInput`: caller (optional, `'user' | 'agent'`), token (optional string for agent)
- `AccessContext`: tenantId, userId, userEmail, role (Role), providerRecordExists (boolean), isSuspended (boolean), flags (PlatformPageFlags)
- `FeatureAccess`: array of enabled feature/page keys (strings matching AdminDomain + services/messages domain key format)
- `SpaceAccess`: SpaceId[] — allowed space IDs from the SPACES registry
- `PageAccess`: spaces (SpaceId[], always present), pages (string[] of enabled page keys), features (string[] of enabled module/feature keys), agent ({ scope: string[], expiresAt: string | null } | null — null for human callers per D-09)
- `AccessResolution`: { spaces: SpaceId[], pages: string[], features: string[], agent: { scope: string[], expiresAt: string | null } | null }
  Export all from barrel.

**resolver.ts** — Implement `resolvePageAccess(ctx: AccessContext, input: AccessInput): AccessResolution` implementing the 5-layer pipeline per D-03:

Layer 0 — Role (synchronous, in-memory ROLE_PERMISSIONS):

- Map role to canonical spaces: ADMIN/BOARD → admin space; PROVIDER → providers space only if providerRecordExists is true (D-04); RESIDENT → core spaces (home, messages) + optional spaces gated by flags
- Core spaces (home, messages) are always included for all non-suspended, authenticated users
- Admin space only when ADMIN_ROLES.includes(role) (reuse ADMIN_ROLES from spaces.ts)
- Providers space only when providerRecordExists === true (NOT when role === 'PROVIDER' per D-04)

Layer 1 — Record existence:

- providerRecordExists gates providers space (D-04). A role-only PROVIDER without a linked provider record does NOT get providers space.
- This is evaluated as a boolean flag on AccessContext — the route handler resolves it from DB.

Layer 2 — Suspension:

- If isSuspended === true, override all spaces to only messages (core), empty pages, empty features
- Suspend check is done by the route handler via requireNotSuspended() — resolver receives the boolean

Layer 3 — Feature flags:

- For each optional space, check flags: services requires flags.services !== false; community requires any of [events, groups, surveys, competitions, news] !== false (same logic as existing getVisibleSpaces community check)
- Map each enabled feature key in PlatformPageFlags to the `pages` array (camelCase key matches page route slugs)
- Features array: list of module names that are enabled (derived from flags + role permissions)

Layer 4 — Agent token (extension point per D-08/D-10):

- When input.caller === 'agent' && input.token is present, set agent: { scope: [], expiresAt: null } (always null — full agent gateway is deferred per CONTEXT deferred section)
- When input.caller is absent or !== 'agent', set agent: null
- This is a reserved extension point; no token validation occurs, no scope resolution — the shape is present to define the contract

**index.ts** — Barrel re-exporting: types (PageAccess, SpaceAccess, FeatureAccess, AccessInput, AccessContext, AccessResolution), resolver (resolvePageAccess).

Follow existing patterns from Phase 41 gate.ts: role lookup via ROLE_PERMISSIONS, barrier at layer 0, early returns for denied states. Use TypeScript strict. No `any`.

Create the canonical access API endpoint at src/app/api/access/route.ts implementing D-01:

**Route handler:**

- Export async GET(request: NextRequest)
- Use `withTenant()` to resolve tenantId (follows all existing API route patterns)
- Use `getSessionAndRole(request)` to get authenticated user (returns null if unauthenticated)
- Unauthenticated callers: return apiSuccess({ spaces: [], pages: [], features: [], agent: null }) — no error, just empty access
- Authenticated callers:
  a. Resolve provider record: call `getProviderRecordForUser(tenantId, session.user.email)` from provider-platform.ts (import directly from @/shared/api/provider-platform — it already uses 'server-only')
  b. Check suspension: call `requireNotSuspended(request)` from auth-utils → isSuspended = result.suspended
  c. Load page flags: call `getPlatformPageFlags(tenantId)` from @entities/tenant/api/flags/platform-flags
  d. Build AccessContext: { tenantId, userId: session.user.id, userEmail: session.user.email ?? null, role, providerRecordExists: providerRecord !== null, isSuspended, flags }
  e. Call resolvePageAccess(ctx, { caller: parseCaller(request) })
  f. Return apiSuccess(accessResolution)

**Caller parsing helper:**

- Extract `caller` and `token` from request.nextUrl.searchParams
- If caller === 'agent' && token is present → AccessInput { caller: 'agent', token }
- Otherwise → AccessInput {}
- Validate token is a non-empty string (basic validation only — no actual token verification per deferred scope)

**Cache strategy (agent's discretion — ISR tag pattern):**

- Set Cache-Control header: `private, max-age=30, stale-while-revalidate=60` (per-user data, short TTL)
- Add `export const maxDuration = 5` (keeps endpoint from running away)
- The access:{userId} tag will be wired for revalidation when role/provider/suspension change events are implemented (this phase just sets the tag pattern in a comment for future invalidation)

**Error handling:**

- Wrap with try/catch → log with createComponentLogger('access') → return apiError('INTERNAL_ERROR', 500, message)
- Tenant not found → 404 via apiError('NOT_FOUND', 404, 'Tenant not found')

**Import pattern:** Import resolvePageAccess + types from `@entities/access` (barrel). Import server utilities from `@api/server` (db, getSessionAndRole, now, requireNotSuspended, withTenant, apiSuccess, apiError). Import getProviderRecordForUser from `@/shared/api/provider-platform`. Import getPlatformPageFlags from `@entities/tenant/api/flags/platform-flags`.

**Exports:** Only export `{ GET }`. No POST/PATCH/DELETE needed.

<threat_model>

## Trust Boundaries

| Boundary                  | Description                                                                                                                                        |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| client → /api/access      | Unauthenticated clients receive empty access (not error) — information disclosure risk if error messages leak tenant existence                     |
| /api/access → DB          | Provider record lookup uses userEmail from session (trusted session data); suspension check via requireNotSuspended reads platformSuspension table |
| /api/access → agent token | Agent token param is parsed but not validated (future extension point) — no token verification means no bypass risk today                          |

## STRIDE Threat Register

| Threat ID | Category               | Component                  | Disposition | Mitigation Plan                                                                                                                                                                                              |
| --------- | ---------------------- | -------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-110-01  | Spoofing               | /api/access GET handler    | mitigate    | getSessionAndRole() validates Better Auth session before resolving access; unauthenticated → empty access                                                                                                    |
| T-110-02  | Information Disclosure | resolvePageAccess resolver | mitigate    | Suspended users get messages-only access; no error messages leak role/tenant info to unauthenticated callers                                                                                                 |
| T-110-03  | Tampering              | Agent token param          | accept      | Agent token is parsed but not validated (deferred to full agent gateway phase). No bypass risk — agent field always returns null/empty scope stub per D-09                                                   |
| T-110-04  | Elevation of Privilege | providerRecordExists flag  | mitigate    | Provider record lookup by session email (trusted), not by caller-provided input. Provider space visibility uses DB-backed existence check, not role string                                                   |
| T-110-05  | Denial of Service      | /api/access GET handler    | mitigate    | maxDuration=5 caps execution time; ISR cache (max-age=30) absorbs repeated requests; DB queries are simple indexed lookups (email on serviceProviders, tenantId on platformSuspension, tenantId on settings) |
| T-110-SC  | Tampering              | npm/pip/cargo installs     | mitigate    | slopcheck + blocking human checkpoint for any new [ASSUMED]/[SUS] packages (no new dependencies introduced by this plan)                                                                                     |
