    Edit src/features/onboarding/ui/steps/InviteStep.tsx to send actual invitations:

    In the handleSave function (currently line 56-61), after saving to onboarding settings, iterate over formData.invites and POST each one to /api/invitations:

    ```typescript
    const handleSave = async () => {
      setSaving(true);
      // First save to onboarding settings (existing behavior)
      const success = await saveStep(4, { invites: formData.invites });
      if (!success) {
        setSaving(false);
        return;
      }

      // Then send actual invitations
      const errors: string[] = [];
      for (const invite of formData.invites) {
        try {
          const res = await fetch('/api/invitations', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({
              email: invite.email,
              name: invite.email.split('@')[0], // Use email prefix as name
              role: invite.role,
              residentType: 'OWNER',
            }),
          });
          if (!res.ok) {
            const data = await res.json();
            errors.push(`${invite.email}: ${data.error || 'Failed'}`);
          }
        } catch (err) {
          errors.push(`${invite.email}: Network error`);
        }
      }

      setSaving(false);
      if (errors.length > 0) {
        // Show errors but still proceed — invitations are best-effort
        console.error('Invitation errors:', errors);
      }
      onNext();
    };
    ```

    The invitation API accepts: email, name, role, residentType, inviterId, organizationId.
    - inviterId and organizationId have placeholder defaults in the API — they'll be filled in later when proper session context is available
    - name: derive from email prefix (e.g., "admin" from "admin@example.com")
    - role: use the selected role (ADMIN, MANAGER, BOARD)
    - residentType: default to 'OWNER'

    Keep the existing saveStep call — it persists invites to onboarding settings for audit trail.
    The new API calls are additive — they create actual invitation records that trigger email sending.

    Do NOT change the invite collection UI (add/remove) — that works correctly.

    2. After the existing isPlatformAdmin check (around line 48-65), add a new block that checks for active assist sessions when a platform admin accesses tenant-scoped routes:

       ```typescript
       // AssistSession scope enforcement for platform admin
       if (user[0]?.isPlatformAdmin && pathname.startsWith('/api/admin/platform/tenants/')) {
         // Extract tenant ID from the URL: /api/admin/platform/tenants/[id]/*
         const pathParts = pathname.split('/');
         const tenantIdIdx = pathParts.indexOf('tenants') + 1;
         const tenantId = pathParts[tenantIdIdx];

         if (tenantId && tenantId !== 'route') {
           // Check for active assist session
           const activeSession = await db
             .select()
             .from(assistSessions)
             .where(
               and(
                 eq(assistSessions.tenantId, tenantId),
                 eq(assistSessions.staffId, session.user.id),
                 eq(assistSessions.isActive, true),
               ),
             )
             .limit(1);

           if (activeSession.length > 0) {
             const session = activeSession[0];
             // Check expiry
             if (session.expiresAt < new Date()) {
               return NextResponse.json(
                 { error: 'Assist session has expired' },
                 { status: 403 },
               );
             }
             // Enforce scope restriction
             if (session.scope === 'metadata') {
               // Allow GET (read metadata) but block POST/PATCH/DELETE (modifications)
               if (request.method !== 'GET') {
                 return NextResponse.json(
                   { error: 'Assist session is metadata-read-only. Use tenant admin panel for modifications.' },
                   { status: 403 },
                 );
               }
             }
           }
         }
       }
       ```

    3. Add the `and` import from drizzle-orm at the top:
       ```typescript
       import { eq, and } from 'drizzle-orm';
       ```

    IMPORTANT: This check only applies when:
    - User is a platform admin (isPlatformAdmin=true)
    - Path is /api/admin/platform/tenants/[id]/*
    - An active AssistSession exists for this staff+tenant pair

    If no assist session exists, the platform admin falls through to the existing isPlatformAdmin check (full access).
    If an assist session exists with scope='metadata', only GET requests are allowed.

    This enforces the "metadata only" guarantee from DISCUSSION.md Path B.
