### 2. `ClientGateContext` interface

```typescript
export interface ClientGateContext {
  role: Role;
  flags: PlatformPageFlags;
  /** Tenant tier (TierLevel) — optional. Client doesn't currently fetch this from /api/flags.
   *  When present, the FeatureToggle layer (Layer 4) uses it. When absent, the layer is permissive. */
  tier?: TierLevel;
}
```

**Decision (per Q1):** `tier` is **optional** because `/api/flags` doesn't currently return it. The client code path works without it (Layer 4 falls through as permissive). When/if the API is extended, `useGateContext()` will populate it.

### 3. `useGateContext()` hook

```typescript
export function useGateContext(): ClientGateContext | null {
  const { flags, isLoading, error } = usePageFlags();

  if (isLoading || error || !flags) {
    return null;
  }

  return {
    role: 'RESIDENT', // TODO Phase 2: integrate with actual session
    flags,
    // tier: undefined (not fetched from /api/flags in Phase 1)
  };
}
```

**No `useMemo` needed** — the hook is lightweight and `usePageFlags()` already handles its own state.

### 4. `canAccessClient()` sync function

```typescript
export function canAccessClient(
  ctx: ClientGateContext,
  feature: FeatureKey,
  opts?: { skipFlag?: boolean }
): GateResult {
  // Layer 0: Role
  const rolePermissions = ROLE_PERMISSIONS[ctx.role];
  if (!rolePermissions) {
    return { allowed: false, reason: 'role' };
  }

  // Layer 1: Tier — SKIPPED on client
  // Server is source of truth; client doesn't fetch tenant.tier from /api/flags

  // Layer 2: Module — SKIPPED on client
  // Server is source of truth; server returns 403 on module-disabled API calls

  // Layer 3: PageFlag
  if (!opts?.skipFlag) {
    const flagKey = (FEATURE_TO_FLAG as Record<FeatureKey, string | null>)[feature];
    if (flagKey !== null) {
      const flagValue = ctx.flags[flagKey as keyof PlatformPageFlags];
      // 'conservation' is a tri-state ('default' | 'managed' | 'external'); treat as enabled when not false
      const flagOk = typeof flagValue === 'boolean' ? flagValue : flagValue !== false;
      if (!flagOk) {
        return { allowed: false, reason: 'flag' };
      }
    }
  }

  // Layer 4: FeatureToggle (only if tier is available in context)
  const registryKey = (FEATURE_TO_REGISTRY as Record<FeatureKey, string | null>)[feature];
  if (registryKey !== null && ctx.tier) {
    const featureOk =
      hasFeature(registryKey, ctx.tier) &&
      canAccessPage(registryKey.replace(/^page\./, ''), ctx.tier);
    if (!featureOk) {
      return { allowed: false, reason: 'feature' };
    }
  }
  // If ctx.tier is not present, Layer 4 is permissive (returns true).
  // This is the Phase 1 trade-off: client doesn't fetch tier; if the page flag
  // is on (Layer 3), client renders. Server will still 403 if tier is wrong.

  return { allowed: true, reason: 'allowed' };
}
```

### 5. `useCanAccess()` convenience hook

A reactive hook that combines `useGateContext()` + `canAccessClient()`:

```typescript
export function useCanAccess(feature: FeatureKey, opts?: { skipFlag?: boolean }): GateResult {
  const ctx = useGateContext();
  if (!ctx) {
    // Conservative default while context is loading
    return { allowed: false, reason: 'role' };
  }
  return canAccessClient(ctx, feature, opts);
}
```

**Important notes:**

- Client is a "best effort" gate — the server is the source of truth.
- Do NOT add a 'use client' directive to `gate-client.ts` — it contains both a hook (client-only) and a pure function (universal). The hook consumers will be 'use client' components.
- Export `ClientGateContext`, `useGateContext`, `canAccessClient`, `useCanAccess`.
- `useGateContext()` returns `null` while loading; consumers must handle this.
- `FEATURE_TO_FLAG` and `FEATURE_TO_REGISTRY` are re-imported from `@shared/api/gate`. The `as Record<FeatureKey, string | null>` cast is safe because the tables are defined that way server-side.
- The `ctx.tier` check on Layer 4 is intentionally optional. Without tier, the layer is permissive — this matches the Phase 1 trade-off (no API change).

### 3. `GateGuardProps` interface

```typescript
interface GateGuardProps {
  /** Feature key (canonical FeatureKey, not 'page.*' string) */
  feature: FeatureKey;
  /** Content to render when access is allowed */
  children: ReactNode;
  /** Fallback content when access is denied (default: null) */
  fallback?: ReactNode;
  /** Render prop: receives GateResult, returns custom UI */
  render?: (props: { result: GateResult }) => ReactNode;
  /** Skip PageFlag layer (for admin pages) */
  skipFlag?: boolean;
  /** Show loading skeleton while context is loading */
  loadingFallback?: ReactNode;
}
```

### 4. `GateGuard` component

```typescript
export function GateGuard({
  feature,
  children,
  fallback = null,
  render,
  skipFlag,
  loadingFallback = null,
}: GateGuardProps) {
  const ctx = useGateContext();

  // Context still loading
  if (!ctx) {
    return <>{loadingFallback}</>;
  }

  const result = canAccessClient(ctx, feature, { skipFlag });

  // Render prop (most specific)
  if (render) {
    return <>{render({ result })}</>;
  }

  // Boolean conditional
  if (result.allowed) {
    return <>{children}</>;
  }

  // Fallback (typically null to hide)
  return <>{fallback}</>;
}
```

### 5. `useGateResult` hook

A reactive hook for components that need the `GateResult` directly without wrapping:

```typescript
export function useGateResult(
  feature: FeatureKey,
  opts?: { skipFlag?: boolean }
): GateResult | null {
  const ctx = useGateContext();
  if (!ctx) return null;
  return canAccessClient(ctx, feature, opts);
}
```
