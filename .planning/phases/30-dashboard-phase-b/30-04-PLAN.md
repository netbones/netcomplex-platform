2. **Create `src/app/(tenant)/dashboard/admin/[domain]/page.tsx`**:
   - Validates domain param against a `ADMIN_DOMAINS` constant
   - Renders the appropriate admin widget for that domain as the full content
   - Domains map to existing admin widgets:
     - users → admin-user
     - maintenance → maintenance-list + maintenance-analytics
     - content → admin-content
     - events → admin-events
     - competitions → admin-competitions
     - resources → admin-resources
     - surveys → admin-surveys
     - announcements → admin-announcements (from Phase 11)
     - system → admin-system + page-settings
   - Breadcrumbs: Home > Dashboard > Admin > [Domain Name]
   - Back link to /dashboard/admin

3. **Create `src/app/(tenant)/dashboard/admin/layout.tsx`**:
   - Simple pass-through layout for admin sub-pages
   - Could include admin-specific header/breadcrumbs, for now just `{children}`

4. **Create `src/widgets/dashboard/ui/MyHomeSpace.tsx`**:
   - Consolidates three areas per user Q3 decision:
     a) **Property Details** — fetched via household relation from user profile
     b) **Household Members** — shows household members list
     c) **Profile Management** — user profile edit form (name, email, phone, avatar)
   - Three sections stacked vertically with card containers
   - Each section has an "Edit" button that opens inline edit mode (or links to existing profile page)
   - **Data sources (clarified per advisory A2):**
     - Current user profile: fetch from `/api/users/[id]` using session userId
     - Household info: the `/api/users/[id]` response includes household and property relations via Prisma includes
     - Property details: accessed via household → `propertyId` relation on the user response
     - **Do NOT use `/api/directory`** — that endpoint returns all residents and is not scoped to the current user
   - Uses existing API endpoints where available
   - If property data is not available (no household linked), shows empty state with link to /directory
   - Responsive: single column
