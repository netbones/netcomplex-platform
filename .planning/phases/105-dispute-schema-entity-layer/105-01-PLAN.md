    **Models to add (6):**

    **DisputeCase** — 22 fields, referenceNumber @unique (DSP-YYYY-NNNN pattern), 4 named user FK relations:
    - `complainantId String` → `complainant user @relation("DisputeComplainant", ...)`
    - `respondentId String?` → `respondent user? @relation("DisputeRespondent", ...)`
    - `assignedModeratorId String?` → `assignedModerator user? @relation("DisputeModerator", ...)`
    - `closedById String?` → `closedBy user? @relation("DisputeClosedBy", ...)`
    - `isConfidential Boolean @default(true)` — Gate G3: complainant identity masked until mediationAcceptedAt set
    - `coolingOffEndsAt DateTime?` — Gate G1: DRAFT→SUBMITTED gate, tenant-configurable 24h–72h
    - Indexes: tenantId, complainantId, respondentId, status, category, assignedModeratorId
    - Relations to children: evidence DisputeEvidence[], events DisputeEvent[], mediationThread DisputeMessage[], notifications DisputeNotification[]

    **DisputeEvidence** — 8 fields, FK disputeId→DisputeCase (Cascade), FK uploadedBy→user
    - Indexes: disputeId, uploadedBy

    **DisputeEvent** — 10 fields, append-only (no @updatedAt), FK disputeId→DisputeCase (Cascade), FK actorId→user (nullable)
    - eventType DisputeEventType, fromStatus/toStatus DisputeStatus? (nullable — event may not be status transition)
    - metadata Json? (flexible payload for audit data)
    - Indexes: disputeId, eventType

    **DisputeMessage** — 11 fields, isInternal Boolean @default(false) (Gate G2: moderator-only notes), FK disputeId→DisputeCase (Cascade), FK senderId→user
    - Indexes: disputeId, senderId

    **DisputeMessageVersion** — 5 fields, preserves originalContent (Gate G2: full version history for CSOS legal defensibility), FK messageId→DisputeMessage (Cascade)
    - originalContent String, editedAt DateTime, createdAt DateTime
    - Index: messageId
    - No updates allowed (append-only preservation record)

    **DisputeNotification** — 7 fields, FK disputeId→DisputeCase (Cascade), FK userId→user
    - type String (not enum — values: 'status_change', 'new_message', 'ruling_issued', 'csos_escalated')
    - read Boolean @default(false)
    - Indexes: disputeId, userId

    Use exact schema from ADVISORY-017 §8 (lines 227–414). Add a `// ── Dispute Resolution ──` section header before the enums. Follow existing naming conventions (PascalCase models, SCREAMING_SNAKE_CASE enum values).

Plan 105-02 Task 3 will handle Drizzle wiring; Task 2 will run `prisma generate` and must report any errors.
