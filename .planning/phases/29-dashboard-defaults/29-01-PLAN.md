Register all missing dashboard widgets (maintenance + admin), update dashboard-config.ts so they render with proper titles/icons, discover the exact tab+layout data shape from source, then write role-seeded default layouts.

<registry_architecture_note>
IMPORTANT — there are THREE distinct registries in this codebase. Do NOT confuse them:

1. **Widget registry** — `src/widgets/dashboard/model/registry.ts` + `widgets.ts`
   A Map-based runtime registry for dashboard widgets. `registerAllWidgets()` in `widgets.ts`
   is the ONLY place that calls `registry.register()`. Tasks 1 and 2 modify this file only.

2. **Feature/tier registry** — `src/entities/tenant/api/features/registry.ts`
   Exports `TIERS`, `FEATURE_REGISTRY`, `WIDGET_REGISTRY`, `isFeatureEnabled`,
   `getFeaturesForTier`. Governs subscription tier gating. DO NOT MODIFY.

3. **Tenant custom sections registry** — `src/entities/tenant/lib/registry.ts`
   Manages custom navigation sections per tenant. DO NOT MODIFY.

`src/entities/widget/model/dashboard-config.ts` imports `isFeatureEnabled` from registry #2
to gate widget visibility by tier — this is correct and expected, not a conflict.

Task 1 and 2 touch registry #1 (widgets.ts). Task 3 touches dashboard-config.ts
(which bridges registry #1 to registry #2's feature gating, but does NOT modify registry #2).
</registry_architecture_note>
