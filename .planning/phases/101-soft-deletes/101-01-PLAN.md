  **Part A — Add `notDeleted()` helper to `db.ts`:**
  In `src/shared/api/db.ts`:
  1. Add `import { isNull, type SQL } from 'drizzle-orm';` to the imports (verify `isNull` source — it may already be imported by another function in that file)
  2. Add the `notDeleted` function. Place it after the `runWithRLS` block (around line 233-234 in the existing file), before the exports block:

```typescript
/**
 * Filter condition that excludes soft-deleted records.
 * Add to any query's WHERE clause for entities with `deletedAt`.
 *
 * @example
 *   db.select().from(contents)
 *     .where(and(notDeleted(contents), eq(contents.tenantId, tenantId)))
 */
export function notDeleted(table: { deletedAt: unknown }): SQL {
  return isNull(table.deletedAt);
}
```

The function is typed with `{ deletedAt: unknown }` minimal interface, which any Drizzle table with a `deletedAt` column satisfies. This avoids circular imports from table definitions.

**Part B — Add barrel export:**
In `src/shared/api/server/index.ts`:

**Part C — Generate and hand-edit migration SQL:**

1. Run: `npx prisma migrate dev --name add_soft_deletes --create-only`
   This creates a new migration directory with auto-generated SQL but does NOT apply it.
   The `--create-only` flag prevents auto-application so we can hand-edit.

2. Read the generated `prisma/migrations/<timestamp>_add_soft_deletes/migration.sql`.

3. Hand-edit the migration SQL to add:

   **3a. Message data migration (BEFORE the DROP COLUMN for isDeleted):**

   ```sql
   -- Migrate existing isDeleted=true records to deletedAt
   UPDATE "Message" SET "deletedAt" = "createdAt" WHERE "isDeleted" = true;
   ```

   Find where Prisma generates `ALTER TABLE "Message" DROP COLUMN "isDeleted"` and add the UPDATE statement IMMEDIATELY before it. The data must be migrated before the column is dropped.

   **3b. Replace Prisma's auto-generated DROP INDEX + ADD UNIQUE with partial unique indexes:**
   Prisma will auto-generate DROP INDEX lines for the removed `@unique` constraints. For each one, REPLACE the pair of (DROP INDEX, CREATE UNIQUE INDEX without WHERE clause in Prisma migration comments) with a single `CREATE UNIQUE INDEX ... WHERE "deletedAt" IS NULL` statement.

   The pattern for each:

   ```sql
   -- Find Prisma's auto-generated lines like:
   -- DropIndex
   -- DROP INDEX IF EXISTS "communityServiceListing_slug_key";
   -- AlterTable (no actual ALTER — Prisma generates it as comment-only)
   -- CreateIndex
   -- CREATE UNIQUE INDEX "communityServiceListing_slug_key" ON "CommunityServiceListing"("slug");

   -- REPLACE WITH:
   DROP INDEX IF EXISTS "communityServiceListing_slug_key";
   CREATE UNIQUE INDEX "communityServiceListing_slug_key"
     ON "CommunityServiceListing"("slug")
     WHERE "deletedAt" IS NULL;
   ```

   **3c. Verify the 5 partial indexes are correct:**
   | Index Name | Table | Column(s) | WHERE |
   |---|---|---|---|
   | `communityServiceListing_slug_key` | CommunityServiceListing | slug | deletedAt IS NULL |
   | `Property_platformAddress_key` | Property | platformAddress | deletedAt IS NULL |
   | `Property_street_unit_key` | Property | street, unit | deletedAt IS NULL |
   | `MaintenanceCategory_tenantId_value_key` | MaintenanceCategory | tenantId, value | deletedAt IS NULL |
   | `GroupMember_userId_groupId_key` | GroupMember | userId, groupId | deletedAt IS NULL |

   **3d. Ensure existing partial unique index naming matches Prisma convention:**
   Prisma names indexes as `TableName_field_key` for single-field and `TableName_field1_field2_key` for composite. The above names match the convention. Verify by checking the auto-generated names in the migration SQL.

4. Review the migration SQL for any `CREATE UNIQUE INDEX` that Prisma auto-generated WITHOUT a `WHERE` clause — those must all be replaced with partial versions. Also watch for Pitfall 1 (RESEARCH.md): Prisma may generate duplicate index creation. Use `IF NOT EXISTS` for idempotency.

If this asks for a migration name (because it detects the existing `--create-only` migration), pass `--name add_soft_deletes` or follow Prisma's interactive prompt.
