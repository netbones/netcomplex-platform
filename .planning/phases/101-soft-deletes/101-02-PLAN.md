**Pattern 1 — DELETE handler: `db.delete()` → `db.update().set({deletedAt})`**

```typescript
// BEFORE:
await db.delete(tableName).where(and(eq(tableName.id, id), eq(tableName.tenantId, tenantId)));

// AFTER:
await db
  .update(tableName)
  .set({ deletedAt: new Date(), updatedAt: new Date() })
  .where(and(eq(tableName.id, id), eq(tableName.tenantId, tenantId)));
```

- Set BOTH `deletedAt` AND `updatedAt` to `new Date()` (per RESEARCH Pitfall — keep timestamps consistent)
- Remove any conditional soft/hard delete branching logic (per D-07 — always soft-delete)
- Keep existing auth/access control unchanged
- Keep existing revalidation calls unchanged (revalidateContent(), revalidateDashboard(), etc.)
- If returning the deleted record, use `.returning()` on the update

**Pattern 2 — GET / LIST handler: add `notDeleted()` to WHERE clause**
Import `notDeleted` from `@api/server` if not already imported (check existing imports first — add to the `@api/server` import block or add a new import: `import { notDeleted } from '@api/server';`).

```typescript
// BEFORE:
.where(and(eq(tableName.id, id), eq(tableName.tenantId, tenantId)))

// AFTER:
.where(and(notDeleted(tableName), eq(tableName.id, id), eq(tableName.tenantId, tenantId)))
```

- Place `notDeleted(tableName)` as the FIRST condition in the `and(...)` array (per RESEARCH — visibility convention)
- Apply to ALL SELECT queries in the file (single-record GET and multi-record LIST)
- For multi-table JOIN queries, add `notDeleted()` for each joined table that has `deletedAt`
- For Group GET handler (groups/[id]/route.ts), the existing join with groupMembers + users needs `notDeleted()` on groups AND groupMembers

**Pattern 3 — PATCH / PUT handler: 410 Gone guard for soft-deleted records**
After the existing record lookup and before any update logic, add:

```typescript
if (existing.deletedAt) {
  return apiGone('This record has been deleted');
}
```

- Import `apiGone` from `@api/server` — verify it's already in the barrel export (from Phase 35, `apiGone` is exported from `@api/server`)
- If the handler does NOT do an explicit record lookup before update, restructure to do one (select `deletedAt` and `id` first, then if not deleted, proceed with update)
- Return `apiGone()` — which returns HTTP 410 with `ERROR_CODES.GONE`

The GET handler for groups/[id] joins groupMembers and users — add `notDeleted(groups)` to the WHERE. The PATCH handler needs the 410 guard.

<threat_model>

## Trust Boundaries

| Boundary                          | Description                                                                         |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| DELETE handler → Drizzle query    | Route issues `db.update` vs `db.delete` — server-side only, never from request body |
| PATCH/PUT handler → Record lookup | Handler checks `deletedAt` before mutation — prevents data resurrection             |
| GET handler → SELECT query        | `notDeleted()` filter prevents soft-deleted records from being returned             |
| Maintenance entity DELETE         | Removed conditional branching — always soft-deletes via `deletedAt`                 |

## STRIDE Threat Register

| Threat ID | Category               | Component                                      | Disposition | Mitigation Plan                                                                                                                                          |
| --------- | ---------------------- | ---------------------------------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-101-05  | Tampering              | DELETE handlers — soft-delete bypass           | mitigate    | `deletedAt` is set server-side (`new Date()`), never read from request body. No route accepts `deletedAt` in Zod schema or body parsing.                 |
| T-101-06  | Tampering              | PATCH/PUT handlers — data resurrection         | mitigate    | 410 Gone check added after record lookup and before any mutation. Guard references `apiGone()` from canonical error taxonomy.                            |
| T-101-07  | Information Disclosure | GET/LIST handlers — deleted record leak        | mitigate    | `notDeleted()` helper applied as first WHERE condition in every SELECT query. Missing filter would be caught by `grep -rl 'notDeleted'` audit in Task 3. |
| T-101-08  | Information Disclosure | Maintenance entity — data loss via hard-delete | mitigate    | Removed conditional branching that could hard-delete on reference-count zero. Always sets `deletedAt`.                                                   |
| T-101-09  | Tampering              | Messages — isDeleted→deletedAt migration gap   | mitigate    | Route no longer references `isDeleted` (verified by grep audit). Migration already migrated existing data (Plan 01).                                     |
