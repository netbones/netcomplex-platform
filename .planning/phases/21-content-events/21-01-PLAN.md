Add content scheduling: date pickers in ContentForm for publishedAt/expiresAt, and API middleware to filter content by publish/expiry dates.

Purpose: The Content model has publishedAt and expiresAt columns but no UI to set them and no API enforcement. Admins need to schedule content (e.g., "publish this news article on Monday", "expire this campaign on Friday"). Without scheduling, all content is manually toggled published/draft with no time control.

Output: ContentForm with date pickers, content API that filters by dates for public queries.

  <action>
    Edit the content API routes to enforce scheduling:

    **In src/app/api/content/route.ts (GET handler):**

    Add date filtering to the where conditions. For PUBLIC queries (users without 'content' permission), filter out:
    - Content where publishedAt is in the future (not yet published)
    - Content where expiresAt is in the past (expired)

    For ADMIN queries (users with 'content' permission), return all content regardless of dates — admins need to see scheduled and expired content to manage it.

    Add these conditions to the whereConditions array:
    ```typescript
    const now = new Date();

    // For public queries, filter by publish/expiry dates
    if (!canViewAll) {
      // Only show content that has been published (publishedAt <= now or publishedAt is null and published is true)
      // AND has not expired (expiresAt is null or expiresAt > now)
      whereConditions.push(
        or(
          isNull(contents.publishedAt),
          lte(contents.publishedAt, now),
        ),
      );
      whereConditions.push(
        or(
          isNull(contents.expiresAt),
          gt(contents.expiresAt, now),
        ),
      );
    }
    ```

    Also update the POST handler to accept publishedAt and expiresAt from the request body:
    ```typescript
    publishedAt: body.publishedAt ? new Date(body.publishedAt) : (body.published ? now : null),
    expiresAt: body.expiresAt ? new Date(body.expiresAt) : null,
    ```

    **In src/app/api/content/[id]/route.ts (GET handler):**

    For the single content item endpoint, also apply the same date filtering for non-admin users. If a non-admin tries to access a not-yet-published or expired content item, return 404.

    Add the imports needed: `or`, `isNull`, `lte`, `gt` from 'drizzle-orm'.

    Do NOT change the PATCH or DELETE handlers — admins should always be able to update or delete any content regardless of schedule.
