    Rewrite `CompetitionList.tsx` to support expandable rows and per-type management.

    **Basic structure:**
    - Keep the existing table header columns: Title, Type (NEW), Start Date, End Date, Status, Entries, Actions
    - Add an expand/collapse chevron on each row (leftmost column)
    - Click expand → shows participant detail panel below the row

    **Expandable row panel:**
    - Animated expand/collapse (max-height transition or simple show/hide)
    - Panel content differs by type:

    **RAFFLE Panel:**
    - Table of participants: Name, Avatar, Joined Date, Status badge
    - Action buttons per participant: none (just view)
    - Admin action at top of panel:
      - If status=ENDED: "Draw Winners" button (prominent, gold/yellow)
      - If status≠ENDED: disabled note "End competition to draw winners"
    - "Draw Winners" click → opens confirmation modal:
      - Number of winners to draw (input, default = competition.winnersCount)
      - "Draw {N} Winners" button
      - Success: toast + refresh

    **PHOTO Panel:**
    - Gallery grid of submissions (3-4 cols): thumbnail image, participant name, status badge
    - Each entry card:
      - submissionUrl thumbnail (img tag, rounded, object-cover, 200px height)
      - Participant name below
      - Current status badge
      - If status=JOINED: "Mark as Winner" button (gold)
      - If status=WINNER: "Winner ✓" badge + prize text + "Remove Winner" button

    **SCORE Panel:**
    - Table: Name, Avatar, Score (inline editable input), Status
    - Score column: input type="number", min=0, max=100 (or custom), step=0.1
    - On blur or Enter → call updateEntry mutation to save score
    - Debounced save (300ms) to avoid excessive API calls
    - Admin action:
      - If status=ENDED: "Auto-select Winners" button
      - Auto-select logic: sort by score descending, take top N (winnersCount), mark as WINNER
      - Success: toast + refresh

    **Shared features (all types):**
    - Fetch participants via `trpc.competitions.listParticipants.useQuery({ competitionId })`
    - Mutations via:
      - `trpc.competitions.updateEntry.useMutation()`
      - `trpc.competitions.markWinner.useMutation()`
      - `trpc.competitions.drawWinners.useMutation()`
    - On mutation success: invalidate participants query to refresh
    - Loading state: spinner inside expanded panel
    - Empty state: "No participants yet"
    - Error state: error message with retry button

    **Preserve existing features:**
    - Keep the edit (pencil icon) link → `/admin/competitions/[id]`
    - Keep the delete flow (confirm/cancel pattern)
    - Keep the status colors
    - Keep the "New Competition" button on the parent page
    - Keep the loading/empty states for the initial table

    **Responsiveness:**
    - On mobile, the expanded panel should be full-width with horizontal scroll for tables
    - Gallery grid goes to 2 columns on tablet, 1 on mobile
