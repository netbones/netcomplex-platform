# Plan 44-03: Audit Closure Wave A

## Goal

Close 4 BD issues from the cleaner_react_architecture audit (r13u, qig, 9xr, 2z4) — fix the tenantConfig barrel export, build a shared HTTP client with typed methods, extract pure domain helpers from hook/service infrastructure, and complete the property shape consolidation audit per UBIQUITOUS_LANGUAGE.md C1 resolution.

## Why this plan exists

`44-CONTEXT.md` defines audit closure wave A as the first of three BD-issue waves (44-03/04/05). These 4 issues are the shallowest items from the cleaner_react_architecture audit — they can be closed without architectural redesign:

1. **r13u** — The `@entities/tenant` barrel is missing 3 module re-exports, producing TS2305 errors in 2 consumers. Minimal fix: add 3 lines to the barrel index.
2. **qig** — ~236 raw `fetch('/api/...')` call sites exist with no shared client, no auth header injection, no envelope unwrapping. Create one shared client and migrate first consumers to establish the pattern.
3. **9xr** — `useIdentity.ts` inlines business logic (`getEffectiveRole`) that should be a pure, testable function. `generateTicketNumber` mixes DB query with string formatting. `maintenance/permissions/index.ts` is a one-line re-export proxy. Extract proper helpers.
4. **2z4** — 5 Property shapes exist across the codebase. Per UBIQUITOUS_LANGUAGE.md C1 resolution, this is primarily an audit — document consumption, verify drift, consolidate only if inconsistent.

    Create `src/shared/api/http-client.ts` — a typed, thin wrapper around `fetch` that provides 4 methods, auth header injection, canonical envelope unwrapping, and a custom error class.

    **File: `src/shared/api/http-client.ts`** (minimum 80 lines)

    ```typescript
    'use client';

    import { authClient } from '@api/auth-client';
    import type { ApiSuccessResponse, ApiErrorResponse } from './api-response';

    // ─── Custom Error Class ────────────────────────────────────────────────

    export class ApiClientError extends Error {
      constructor(
        public readonly statusCode: number,
        public readonly errorCode: string,
        message: string,
        public readonly details?: unknown
      ) {
        super(message);
        this.name = 'ApiClientError';
      }
    }

    // ─── Helpers ───────────────────────────────────────────────────────────

    async function getAuthHeaders(): Promise<Record<string, string>> {
      const session = await authClient.getSession();
      if (session?.data?.session?.token) {
        return { Authorization: `Bearer ${session.data.session.token}` };
      }
      return {};
    }

    async function getRequestId(): Promise<string | undefined> {
      try {
        const { getRequestId } = await import('./observability');
        return getRequestId();
      } catch {
        return undefined;
      }
    }

    async function request<T>(
      method: string,
      path: string,
      body?: unknown,
      params?: Record<string, string>
    ): Promise<T> {
      const url = new URL(path, window.location.origin);
      if (params) {
        Object.entries(params).forEach(([key, value]) => url.searchParams.set(key, value));
      }

      const headers: Record<string, string> = {
        'Content-Type': 'application/json',
        ...(await getAuthHeaders()),
      };
      const requestId = await getRequestId();
      if (requestId) headers['X-Request-Id'] = requestId;

      const res = await fetch(url.toString(), {
        method,
        headers,
        body: body !== undefined ? JSON.stringify(body) : undefined,
      });

      if (!res.ok) {
        let errorBody: ApiErrorResponse | null = null;
        try {
          errorBody = (await res.json()) as ApiErrorResponse;
        } catch {
          // Response body is not valid JSON
        }
        const error = errorBody?.error;
        throw new ApiClientError(
          res.status,
          error?.code ?? 'UNKNOWN_ERROR',
          error?.message ?? `Request failed with status ${res.status}`,
          error?.details
        );
      }

      // Handle 204 No Content
      if (res.status === 204) {
        return undefined as unknown as T;
      }

      const json = (await res.json()) as ApiSuccessResponse<T> | T;

      // Unwrap {success, data} envelope if present (duck-type check per useApiToast pattern)
      if (
        json &&
        typeof json === 'object' &&
        'success' in json &&
        'data' in json &&
        (json as ApiSuccessResponse<T>).success === true
      ) {
        return (json as ApiSuccessResponse<T>).data;
      }

      // Passthrough for unwrapped responses
      return json as T;
    }

    // ─── Public API ────────────────────────────────────────────────────────

    export function apiGet<T>(path: string, params?: Record<string, string>): Promise<T> {
      return request<T>('GET', path, undefined, params);
    }

    export function apiPost<T>(path: string, body?: unknown): Promise<T> {
      return request<T>('POST', path, body);
    }

    export function apiPatch<T>(path: string, body?: unknown): Promise<T> {
      return request<T>('PATCH', path, body);
    }

    export function apiDelete<T>(path: string): Promise<T> {
      return request<T>('DELETE', path);
    }
    ```

    **Key design decisions:**
    - **`'use client'`** — The module uses `authClient.getSession()` which is a client-side hook. It must be a client module.
    - **`request<T>()` internal helper** — Avoids repeating the call logic across 4 methods. Not exported (internal utility).
    - **Auth header injection** — Uses the `authClient.getSession()` pattern from `src/app/providers.tsx:32-36`. Returns empty object if no session (unauthenticated requests still work).
    - **X-Request-Id header** — Dynamically imports `getRequestId` from `observability.ts` for request correlation. Uses try/catch in case the module fails to load in test environments.
    - **Envelope unwrap** — Duck-type check matching the `useApiToast` pattern: checks for `success === true && data` at runtime. Passthrough for unwrapped responses (some endpoints return arrays directly).
    - **`ApiClientError`** — Extends `Error` with `statusCode`, `errorCode`, and optional `details`. Enables callers to catch and extract structured error info.
    - **No body for GET/DELETE** — REST convention. POST/PATCH accept optional body.
    - **Origin-relative URLs** — Uses `window.location.origin` to build full URLs, supporting same-origin proxy paths.
