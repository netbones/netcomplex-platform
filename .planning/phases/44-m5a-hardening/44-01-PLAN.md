# Plan 44-01: Steiger FSD Linter Integration

## Goal

Install Steiger (the official Feature-Sliced Design linter) and integrate it into the project's dev cycle. Surface the full FSD debt via a baseline scan, file follow-up BD issues for the major debt clusters, and configure the project so future FSD violations are caught automatically.

## Why this plan exists

The team's manual ESLint `no-restricted-imports` patterns catch deep imports across FSD layers, but miss:

1. Layer hierarchy (a `shared` module importing from `entities`)
2. Cross-imports within the same layer (e.g., `entities/booking` importing from `entities/tenant`)
3. Public API completeness (slices that import from a barrel that doesn't re-export the symbol — the bug class behind soralia-village-r13u)
4. Public API sidestep (the bug class behind soralia-village-de8x)
5. Missing public APIs (slices without `index.ts`)
6. Insignificant slices (dead code detection)
7. Layer name typos (the bug class behind the `lib18n` typo — a future-proofing measure)

Steiger (`@feature-sliced/steiger-plugin`) is the official FSD linter and covers all of these. The ESLint config in `eslint.config.js` was a stopgap; Steiger is the proper solution.

`@feature-sliced/eslint-config` was considered and rejected: it's been abandoned (v0.1.1, last published 2025-05), while Steiger is actively maintained (v0.5.12, published 2026-05-14).

## Baseline findings (2026-06-07)

Steiger's first scan of `./src` (default config) found **582 FSD violations** across the codebase:

| Rule | Count | Severity | Notes |
|------|------:|----------|-------|
| `no-public-api-sidestep` | 461 | 222 err, 239 warn | All from `@api/*` alias bypassing `@shared/api` barrel |
| `forbidden-imports` (cross + higher) | 91 | 45 err, 46 warn | Layer hierarchy + cross-slice |
| `insignificant-slice` | 17 | 17 err | Slices with no/few references (dead code) |
| `public-api` (missing) | 7 | 7 err | Slices without `index.ts` |
| `typo-in-layer-name` | 1 | 1 err | `src/types` should be `pages` |
| (other) | 5 | mixed | `shared-lib-grouping`, `no-segmentless-slices`, etc. |

### Top debt clusters (will be filed as separate BD issues / Phase 44 follow-up plans)

1. **`@api/*` barrel-sidestep cluster (461 violations)**: The `@api/*` path alias in `tsconfig.json:24` maps to `./src/shared/api/*`, but `src/shared/api/index.ts` (the barrel) does not re-export most of the submodules. So `import { foo } from '@api/db'` is technically `import { foo } from '@shared/api/db'` — a deep import that bypasses the barrel. Used in ~120+ files. **Decision needed**: either (a) re-export everything from `src/shared/api/index.ts`, (b) deprecate the `@api/*` alias in favor of explicit `@shared/api/<submodule>` paths, or (c) keep `@api/*` as a documented non-public-API shortcut and configure Steiger to ignore it.
2. **`entities/tenant` fan-in cluster (9 cross-imports)**: 9 different entity slices (`admin`, `booking`, `content`, `events`, `identity`, `maintenance`, `user`, `widget`, ...) import from `entities/tenant`. This violates FSD's "slices within a layer are independent" rule. Need to identify which tenant exports are needed and either (a) move them to `shared/`, (b) re-architect the consumer slices to not need them, or (c) accept these as "this is a legitimate cross-slice contract" and configure Steiger to allow them.
3. **`entities/admin` fan-in cluster (26 cross-imports)**: 26 widgets/features import from `entities/admin`. Same architectural question.
4. **`shared/api/*` → `entities/*` cluster (20 violations)**: `gate.ts`, `feature-gate.ts`, `auth.ts`, `auth-utils.ts`, `schemas.ts`, etc. import from `entities/`. The gate/auth logic depends on entity types, which is a layer-hierarchy violation. May require restructuring (e.g., defining the contracts in `shared/` and having `entities/` implement them).
5. **`shared/lib/*` → `entities/*` cluster (8 violations)**: `navigation-config.ts`, `navigation.ts`, `nav-utils.ts`, `gate-client.ts`, `Header.tsx`, `MobileMenu.tsx` import from `entities/`. Same architectural problem as #4.
6. **`features/pricing` → `app` cluster (1 violation)**: `PricingCards.tsx` imports from the `app` layer. Needs investigation.
7. **Missing public APIs (7 slices)**: `entities/content`, `entities/user`, `features/announcements`, `features/auth`, `features/marketing`, `features/platform`, `features/pricing` — none have `index.ts`. Some of these also have "no references" warnings, suggesting they may be dead code.
8. **`src/types` typo (1 violation)**: The folder `src/types/` is at the wrong FSD layer. Likely a legacy folder that should be moved to `src/shared/types/` or `src/pages/types/` (Steiger's suggestion).
9. **Insignificant slices (17)**: `entities/content`, `entities/identity`, `entities/user`, `features/admin`, `features/booking`, `features/chat`, `features/marketing`, `features/platform`, `features/pricing`, `features/survey-builder`, `widgets/chat`, `widgets/maintenance`, etc. Need investigation — some may be legacy code, others may be referenced indirectly.

## Plan steps

### Step 1: Install Steiger

```bash
pnpm add -D steiger@0.5.12 @feature-sliced/steiger-plugin@0.5.8
```

(Already done in worktree `phase-44-hardening` for baseline scan.)

### Step 2: Create `steiger.config.js` with project-specific rules

```js
// steiger.config.js
import { defineConfig } from 'steiger';
import fsd from '@feature-sliced/steiger-plugin';

export default defineConfig([
  ...fsd.configs.recommended,
  {
    rules: {
      // Phase 44 baseline: report violations but do not fail the build.
      // As we triage and remediate each cluster (44-03, 44-04, ...), rules
      // will be tightened to 'error' one at a time.
      'fsd/no-public-api-sidestep': 'warn',
      'fsd/forbidden-imports': 'warn',
      'fsd/insignificant-slice': 'warn',
      'fsd/public-api': 'warn',
      'fsd/typo-in-layer-name': 'error',
      'fsd/shared-lib-grouping': 'warn',
      'fsd/segments-by-purpose': 'warn',
      'fsd/no-segmentless-slices': 'warn',
      'fsd/no-reserved-folder-names': 'warn',
      'fsd/inconsistent-naming': 'warn',
      'fsd/no-processes': 'error', // we don't use the deprecated processes layer
    },
  },
  {
    // Allow documented sidesteps:
    files: ['src/**/*.{ts,tsx}'],
    rules: {
      // i18n is a client-only module that the barrel deliberately excludes
      // (to avoid pulling react-i18next into server bundles). See
      // soralia-village-de8x for context. Each consumer of @shared/lib/i18n
      // has an eslint-disable-next-line comment with the same justification.
      'fsd/no-public-api-sidestep': ['warn', { allow: ['@shared/lib/i18n'] }],
    },
  },
]);
```

### Step 3: Add `pnpm fsd:check` script

In `package.json`:

```json
{
  "scripts": {
    "fsd:check": "steiger ./src"
  }
}
```

### Step 4: Add CI workflow

Create `.github/workflows/fsd-lint.yml`:

```yaml
name: FSD Lint
on:
  pull_request:
    paths:
      - 'src/**'
      - 'steiger.config.js'
      - 'package.json'
      - 'pnpm-lock.yaml'
  push:
    branches: [main, dev]
    paths:
      - 'src/**'
      - 'steiger.config.js'
jobs:
  fsd-lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'pnpm'
      - run: pnpm install --frozen-lockfile --ignore-scripts
      - run: pnpm fsd:check
```

### Step 5: Wire Steiger into pre-commit (staged FSD files only)

Add a script `scripts/steiger-staged.sh`:

```bash
#!/usr/bin/env bash
# Run Steiger on staged FSD files only. Skips on no-op commits.
set -e
STAGED=$(git diff --cached --name-only --diff-filter=ACMR | grep -E '^src/.*\.(ts|tsx)$' || true)
if [ -z "$STAGED" ]; then
  exit 0
fi
# Steiger scans the whole tree; we can't scope to files yet, but exit-code
# non-zero on staged-area violations will block the commit.
pnpm fsd:check
```

Add to `.husky/pre-commit` (after the lint-staged step):

```bash
./scripts/steiger-staged.sh
```

### Step 6: Document in AGENTS.md

Add a new section under "Coding Standards" or "Tooling" describing:

- What Steiger is
- How to run it (`pnpm fsd:check`)
- How to interpret findings (which rules map to which FSD concepts)
- How to add a documented sidestep (`steiger.config.js` → `files:` block)

### Step 7: File BD issues for each debt cluster

Each cluster becomes its own BD issue with the file list from the baseline scan. These will inform Phase 44 follow-up plans (44-08+).

### Step 8: Update `eslint.config.js` comment

Add a comment at the top of `eslint.config.js` explaining the relationship between the manual FSD patterns and Steiger:

```js
// Note: Feature-Sliced Design boundaries are primarily enforced by Steiger
// (see steiger.config.js and `pnpm fsd:check`). The no-restricted-imports
// rules below are a fast first-line defense for the deep-import case; Steiger
// is the source of truth for layer hierarchy, cross-slice, and public-API
// violations. Do not add new FSD rules here without also adding the
// equivalent in steiger.config.js.
```

- The pre-commit hook runs full `pnpm fsd:check` on every commit, which is slow (~10s). Acceptable for now; can be optimized later by caching or scoping to staged files only (Steiger doesn't yet support per-file scanning).
- 582 baseline warnings will appear in CI. Will accept these as the "debt inventory" and tighten rules one cluster at a time as Phase 44 follow-up plans close each cluster.
