## Context

Phase 44-04 eliminated 389 `@api/*` sidestep violations. The remaining FSD debt falls into two categories of **forbidden-imports** (layer inversions and cross-slice imports), tracked by three BD issues:

| BD   | Violation type             | Current count      | Description                                                                                                                                                                                                                                                                                                                                              |
| ---- | -------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| znjo | shared → entities          | 13 files           | `src/shared/api/*` and `src/shared/lib/*` import from `@entities/tenant`, `@entities/content`, `@entities/booking`, `@entities/events`, `@entities/maintenance`, `@entities/chat`, `@entities/survey`. Shared is the foundation layer — it must never reach up to entities.                                                                              |
| bszk | entities/tenant shim       | 118 consumer files | `entities/tenant/api/permissions.ts` and `entities/tenant/api/types.ts` are re-export shims from `@shared/lib`. All 118 consumers importing `{ ROLE_PERMISSIONS, type Role, type Tenant, type TenantTier, ... }` from `@entities/tenant` should import directly from `@shared/lib`. Once migrated, the shims and their barrel re-exports can be deleted. |
| nf5r | entities/admin cross-slice | 15 files           | Admin pages import widget components from `@widgets/admin/ui/CompetitionList` etc. (cross-slice sidesteps). Also `src/widgets/dashboard/model/widgets.ts` has a cross-import.                                                                                                                                                                            |

**Why these are grouped:** All three are FSD boundary violations in the same cluster. Fixing bszk is a prerequisite for znjo (the shims are the indirection layer that lets shared→entities exist). Fixing znjo reduces the "worst class" of FSD violation (foundation reaching up). nf5r is a smaller but related cross-slice issue.

## Goal

1. **bszk:** Migrate all 118 `@entities/tenant` consumers of shim-re-exported symbols to `@shared/lib`, then delete `entities/tenant/api/permissions.ts` and `entities/tenant/api/types.ts`.
2. **znjo:** Fix all 13 `src/shared/* → @entities/*` forbidden imports by inverting the dependency (move the entity concern down to shared, or inject it via parameters).
3. **nf5r:** Fix all 15 admin cross-slice sidesteps by ensuring proper public API usage.

## Architecture Decisions

### AD-1: bszk — Direct import from @shared/lib

**Current flow:** consumer → `@entities/tenant` (barrel) → shim → `@shared/lib`
**Target flow:** consumer → `@shared/lib` directly

The shims exist for backward compatibility from BD 08st. The symbols they re-export (`ROLE_PERMISSIONS`, `Role`, `Tenant`, `TenantTier`, `PlatformPageFlags`, etc.) are already defined in `@shared/lib`. The migration is a find-replace per symbol:

| Symbol                                          | Current import     | Target import |
| ----------------------------------------------- | ------------------ | ------------- |
| `ROLE_PERMISSIONS`                              | `@entities/tenant` | `@shared/lib` |
| `type Role`                                     | `@entities/tenant` | `@shared/lib` |
| `type Permission`                               | `@entities/tenant` | `@shared/lib` |
| `hasPermission`, `isAdmin`, etc.                | `@entities/tenant` | `@shared/lib` |
| `type Tenant`                                   | `@entities/tenant` | `@shared/lib` |
| `type TenantTier`                               | `@entities/tenant` | `@shared/lib` |
| `type PlatformPageFlags`                        | `@entities/tenant` | `@shared/lib` |
| `canAccessPage`, `hasFeature`, `type TierLevel` | `@entities/tenant` | `@shared/lib` |

Many consumers also import **non-shim** symbols from `@entities/tenant` (e.g. `withTenant`, `FeatureGate`, `TenantProvider`, `FEATURE_REGISTRY`). These must stay — we split the import into two lines:

```typescript
// Before:
import { ROLE_PERMISSIONS, type Role, withTenant, FeatureGate } from '@entities/tenant';

// After:
import { ROLE_PERMISSIONS, type Role } from '@shared/lib';
import { withTenant, FeatureGate } from '@entities/tenant';
```

After all shim symbols are migrated, remove the shims and their barrel re-exports.

- `auth.ts` → `tenantConfig` — must be moved to shared
- `feature-gate.ts` / `gate.ts` → `isModuleEnabled`, `withTenant` — dependency injection or relocation

## Risk Assessment

| Risk                                                                 | Mitigation                                                                                |
| -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 118-file migration introduces typos                                  | Sub-batch by directory; `pnpm typecheck` after each batch                                 |
| `schemas.ts` deletion breaks many consumers                          | Task 2 redirects consumers BEFORE deleting                                                |
| `tenantConfig` move breaks auth                                      | Move first, verify with `pnpm build`, then redirect consumer                              |

| Removing shims breaks `@entities/tenant` barrel for non-shim imports | Only remove shim re-exports; `withTenant` and other genuine entity exports stay in barrel |
