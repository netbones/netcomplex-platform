NetComplex modular services architecture — tier model, schema design, and gate patterns

Tier model
Four tiers
CoreAlways on. Every tenant gets these — auth, dashboard shell, notifications, settings.
StandardDefault for most tenants. Directory, groups, maintenance, content, community services.
PremiumOpt-in paid modules. Bookings, premium seats, property listings, agent marketplace.
EnterpriseBespoke or high-cost. Custom sections, advanced analytics, white-label domains.

Why not just json[] on tenants?
query A junction table lets you query "all tenants with bookings enabled" without scanning jsonb. Critical for billing and analytics.
config The config jsonb column on tenant_modules stores per-module overrides — e.g. booking slot limits, custom labels — without polluting the tenants table.
audit enabled_at gives you a free activation timeline for billing, support, and churn analysis.
tier min_tier on platform_modules lets you validate at the platform level — a tenant on Standard cannot enable a Premium module even if they call the API directly.
Relation to existing tenants.ts
Keep tenants.ts as-is for branding + domain config. Add tier enum column to it ('standard' | 'premium' | 'enterprise'). The two new tables hang off it via tenant_id FK.
Enforcement patterns
Three gates — use all three
middleware Resolve tenant tier from the tenants table and attach to request context alongside tenant_id. Used for coarse-grained route protection — redirect to upgrade page if tier insufficient before any DB work happens.
FeatureGate React component that reads the resolved tenant module list from context. Wraps page sections, nav items, and dashboard widgets. Renders a locked/upgrade state rather than a redirect — better UX for in-app gating.
API layer Every API route for a gated feature calls assertModuleEnabled(tenantId, 'bookings') as its second operation after withTenant(). Server-side enforcement is non-negotiable — client gates are UX only.
DB query Drizzle helper requireModule(tenantId, key) — joins tenant_modules, throws 403 if not enabled. Used inside service-layer functions so even tRPC and cron jobs are gated consistently.
